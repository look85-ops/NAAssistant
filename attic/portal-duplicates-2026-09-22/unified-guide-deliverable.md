## Введение

Вы слышали про AI-агентов, но думаете «это для программистов»? Вы уже пробовали ChatGPT, но промпты пишутся «на глаз» и результат нестабилен?

**Что внутри:**

- **Часть 1.** Конспект гайда «Как собрать своего AI-агента без единой строки кода» — что такое агент, как запустить за 30 минут, как давать задачи, 5 готовых шаблонов.

**Для кого:** методисты, L&D-специалисты, EdTech-продюсеры — все, кто проектирует обучение и хочет усилить себя AI.

## Часть 1. AI-агенты — краткий конспект

*По мотивам гайда «Как собрать своего AI-агента без единой строки кода»*

### Что такое AI-агент

**Чат** — это прохожий на улице. Спросил → ответил → забыл.
**Агент** — это сотрудник, которому вы дали должностную инструкцию. Один раз описали: кто вы, что нужно, как отвечать, что важно. Дальше он помнит контекст, файлы, решения.

### Три уровня AI-помощника

| Уровень | Что это | Когда хватает |
|---|---|---|
| 1. Обычный чат | Claude.ai, ChatGPT, DeepSeek | Разовые вопросы, черновики |
| 2. Project | Чат + постоянная инструкция + файлы | Одна повторяющаяся задача |
| 3. Агент (opencode) | AI в папке на компьютере: видит файлы, редактирует, копит знания | Несколько проектов, суб-агенты, автоматизация |

Гайд — про третий уровень. Принципы работают на всех.

### Что агенты умеют и не умеют

**Умеют:** помнить контекст месяцами, читать файлы (PDF, Word, Excel), редактировать документы, собирать сайты, считать метрики, работать в связке (один придумывает, второй проверяет, третий пишет).

**Не умеют:** читать мысли, гарантировать 100% точность, заходить в личные кабинеты без интеграции, заменить экспертное суждение.

### Запуск за 30 минут

1. Компьютер с интернетом + почта + API-ключ ($5–10/первый месяц, можно бесплатно).
2. Установка opencode: Desktop-версия с opencode.ai — как обычная программа. Или одной командой в терминале.
3. API-ключ: Anthropic (Claude) ~$10–30/мес активного использования; OpenRouter — доступ к бесплатным моделям.

### Формула первого промпта (7 блоков)

1. **КТО Я** — имя, возраст, профессия, обстоятельства
2. **ЗАДАЧА** — для чего агент
3. **ОБРАЩЕНИЕ** — на «ты» или «вы», как звать
4. **СТИЛЬ ОТВЕТА** — длина, формат, что не использовать
5. **ГРАНИЦЫ** — темы и формулировки, которых избегать
6. **ПРИНЯТИЕ РЕШЕНИЙ** — что агент делает сам, что — с подтверждением
7. **ПРЯМО СЕЙЧАС** — первое задание: развернуть структуру, задать вопросы

### Как давать задачи

Формула: **[ЧТО]** + **[ДЛЯ КОГО]** + **[ФОРМАТ]** + **[С УЧЁТОМ ЧЕГО]** + пример.

Плохо: «Напиши пост».
Хорошо: «Напиши пост для методологов корпобучения: история из практики + инсайт + вопрос. 150 слов. Тон — как в моих прошлых постах».

### Как исправлять и обучать

Три типа обратной связи:
- **Разовая:** «Перепиши покороче» — правит, но не запоминает.
- **Правило на будущее:** «Всегда пиши покороче, запиши в knowledge» — сохранится.
- **Обновление контекста:** «Мой рынок поменялся, обнови AGENTS.md» — правит «конституцию».

### Уровни доверия

- Зелёный (сам): правит файлы, ведёт бэклог, обновляет knowledge
- Жёлтый (с ОК): предлагает, вы утверждаете (черновики, посты)
- Красный (только вы): стратегия, деньги, личные данные

Чем дольше работаете — тем больше уходит в зелёный.

### Библиотека промптов (из гайда)

5 готовых шаблонов суб-агентов:
1. **Карьерный стратег** — резюме, вакансии, сопроводительные
2. **Аналитик опросов** — метрики, инсайты, A/B-гипотезы
3. **Планировщик недели** — таблица, приоритеты, ретроспектива
4. **Ассистент для творческого проекта** — обсуждает, правит, не пишет за вас
5. **Редактор постов** — правки стиля, хьюманайзер (вычищает «AI-следы»)

### Частые проблемы

| Проблема | Причина | Решение |
|---|---|---|
| Делает не то | Неоднозначный запрос | Уточнить, показать пример |
| Забывает правила | Правило в разовом чате | «Запиши в AGENTS.md» |
| Дорого | Длинный контекст | Сжать контекст, бесплатные модели для мелочей |
| Медленно | Много файлов / медленная модель | Только нужные файлы, сменить модель |
| Сломал файл | Широкий запрос | Конкретные файлы, git для отката |

### Когда НЕ нужен агент

- Одна разовая задача → обычный чат.
- Нужен лицензированный специалист (юрист, врач).
- Нужны 100% точные данные.
- Хотите заменить человеческий контакт.

## Часть 2. 7 промптов для методиста

Каждый промпт — в XML-структуре. Копируете → заменяете `[текст в скобках]` → отправляете в чат с AI.

### 1. План онбординга под роль

```xml
<role>Методист корпоративного обучения, проектирующий онбординг-программы. Работаешь с конкретными ролями, инструментами и календарём компании. Не даёшь абстрактных советов.</role>
<context>Руководитель нанимает [ДОЛЖНОСТЬ] в отдел [НАЗВАНИЕ]. Компания — [ОТРАСЛЬ], [РАЗМЕР] сотрудников. Новичок: [с опытом / джуниор / после смежной роли]. Формат: [офис / удалёнка / гибрид]. Инструменты: [перечислить].</context>
<task>Составь 2-недельный план онбординга по дням. Выход: таблица. Первая неделя — ощущение «я справляюсь». Вторая — первые самостоятельные задачи.</task>
<format>Таблица: День | Тема дня | Действия новичка | Встречи (с кем) | Чек-поинт (1 вопрос руководителю) | Ответственный</format>
<constraints>Пиши на уровне 9 класса. Дай конкретные действия (имя документа, название системы). Не более 3 встреч в день. Делай перерывы: день 3 и день 8 — без новых встреч, только самостоятельная работа.</constraints>
<examples>День 1. Тема: «Кто есть кто». Действия: получить доступы (почта, Slack, LMS — список от IT), прочитать «Welcome Book» (ссылка), заполнить профиль в HR-системе. Встречи: HR (30 мин, оргвопросы), руководитель (15 мин, цели на неделю). Чек-поинт: «Что было самым непонятным сегодня?»</examples>
```

### 2. Welcome-письмо от руководителя

```xml
<role>Руководитель отдела, который пишет человеческие письма. Твой тон — тёплый, личный, без «рады приветствовать в нашей дружной команде». Ты обращаешься к конкретному человеку.</role>
<context>Новый сотрудник [ИМЯ] выходит на роль [ДОЛЖНОСТЬ] в отдел [НАЗВАНИЕ]. Первый рабочий день — [ДАТА]. Команда: [N] человек. Руководитель — [ИМЯ РУКОВОДИТЕЛЯ].</context>
<task>Напиши Welcome-письмо от лица руководителя. 3–4 абзаца. Письмо должно дать ощущение «меня ждали» и «я на своём месте».</task>
<format>Абзац 1 — личное обращение и радость от прихода именно этого человека. Абзац 2 — почему выбрали именно его (1–2 конкретных качества или опыта). Абзац 3 — что ждёт в первый день и первую неделю (без пугающих слов). Абзац 4 — к кому обращаться с вопросами и контакт.</format>
<constraints>Без канцелярита. Без «мы». Пиши «я» от лица руководителя. Используй имя новичка минимум 2 раза. Длина — 120–180 слов.</constraints>
<examples>(Имя), привет! Я рад, что ты с нами — твои кейсы по (теме) на (прошлом месте) меня впечатлили. Именно поэтому я хочу, чтобы ты взял (конкретный участок) — вижу, что ты с этим справишься. В первый день тебя встретит (имя HR), покажет всё и расскажет. А во вторник я жду тебя на 15-минутный зум — просто познакомимся. Пиши в любое время, я на связи. (Имя руководителя)</examples>
```

### 3. Чек-лист первого дня

```xml
<role>HR-специалист, отвечающий за онбординг. Ты знаешь, что первый день — самый важный: новичок либо остаётся, либо мысленно уходит. Твоя задача — сделать его максимально ясным и спокойным.</role>
<context>Новый сотрудник [ИМЯ] — [ДОЛЖНОСТЬ] в [КОМПАНИЯ]. Первый день: [ДАТА]. Формат: [офис / удалёнка / гибрид]. Часовой пояс: [UTC+X].</context>
<task>Составь почасовой чек-лист первого дня. С 9:00 до 18:00.</task>
<format>Таблица: Время | Действие | Кто проводит | Что подготовить | Результат (что должно быть сделано)</format>
<constraints>Пиши на уровне 9 класса. Включай 15-минутные буферы между блоками. Обед — 45 минут, не ранее 12:30. Последний час — самостоятельное изучение, без встреч. Каждое действие — с глаголом (получить, заполнить, встретиться, прочитать).</constraints>
<examples>09:00–09:30 | Получить ноутбук и доступы | IT-специалист | Ноутбук, список паролей | Ноутбук включён, почта открыта, Slack запущен. 09:30–09:45 | Встреча с HR | HR-менеджер | Welcome Book (распечатать) | Подписаны NDA и заявление о приёме</examples>
```

### 4. AI-бадди для новичка

```xml
<role>Внутренний помощник компании [НАЗВАНИЕ]. Ты — AI-бот, который отвечает на вопросы новых сотрудников по документам компании. Твой тон — ровный и дружелюбный, без панибратства.</role>
<context>Ты отвечаешь на вопросы новичков в первые 30 дней работы. База знаний — документы компании: регламенты, инструкции, FAQ, карта офиса, контакты. Целевая аудитория: методисты и L&D-специалисты — люди без технического бэкграунда.</context>
<task>Отвечай на вопросы новичков, опираясь только на базу знаний. Если в базе нет ответа — честно скажи: «Этого нет в моей базе. Спроси у [ИМЯ HR / КОНТАКТ]». Никогда не придумывай правила.</task>
<format>Каждый ответ: 3–5 предложений. Сначала — прямой ответ. Потом — где найти подробнее (документ, раздел). В конце — контакт человека, если нужно уточнить.</format>
<constraints>База знаний — единственный источник. Не давай советов «как лучше». Не оценивай вопросы. Если вопрос не по теме — перенаправь к HR. Никогда не используй слова «возможно», «наверное», «кажется».</constraints>
<examples>Вопрос: «Как подключиться к VPN?» Ответ: «Скачай клиент по ссылке (url). Логин и пароль — в письме от IT (тема «Доступы», отправлено в первый день). Если не находишь письмо — напиши Ивану из IT: ivan@company.com»</examples>
```

### 5. Оценка онбординга через 30 дней

```xml
<role>Методист-аналитик, разрабатывающий опросники для оценки онбординга. Ты измеряешь, а не оцениваешь. Твоя цель — выявить паттерны, а не «нравится / не нравится».</role>
<context>Опрос проводится через 30 дней после выхода новичка. Целевая аудитория: методисты и L&D-специалисты. Опрос анонимный. Цель: понять, что в онбординге работает, а что — нет, и что нужно менять.</context>
<task>Составь опросник из 7 вопросов. 5 — с оценкой по шкале 1–5. 2 — открытые. Вопросы должны выявлять конкретные зоны для улучшений.</task>
<format>Для каждого вопроса: формулировка + шкала. Открытые вопросы — с местом для свободного ответа (3–5 предложений). В конце — инструкция: «Опрос займёт 5 минут. Ответы анонимны. Спасибо за честность».</format>
<constraints>Шкала 1–5, где 1 = «совсем нет», 5 = «полностью да». Избегай двойных отрицаний. Каждый вопрос — про один аспект. Открытые вопросы начинай с «Что», а не «Почему».</constraints>
<examples>1. «В первый день я чётко понимал, что мне делать и к кому идти» — шкала 1–5. 2. «У меня был доступ к нужным инструментам (почта, Slack, LMS) к концу первого дня» — шкала 1–5. 7. «Что самое полезное в онбординге? Что стоило бы убрать или изменить?» — открытый.</examples>
```

### 6. AI-ассистент методиста

```xml
<role>AI-ассистент методиста корпоративного обучения. Ты помогаешь разрабатывать учебные материалы и проверяешь их. Ты — инструмент, не замена. Финальное решение — за человеком.</role>
<context>Методист разрабатывает учебную программу для [АУДИТОРИЯ] по теме [ТЕМА]. Формат: [онлайн-курс / очный тренинг / смешанное]. Длительность: [ЧАСОВ]. Текущий этап: [проектирование / наполнение / проверка].</context>
<task>Работаешь в двух режимах: РЕЖИМ 1 «Разработка» — генерируешь учебные блоки по шаблону, предлагаешь активности под цель. РЕЖИМ 2 «Проверка» — проверяешь готовый материал: логика, полнота, уровень сложности, метрики оценки.</task>
<format>РЕЖИМ 1: Блок → Цель блока (измеримая) → Содержание (3–5 тезисов) → Активность (название + инструкция) → Способ проверки. РЕЖИМ 2: Параметр проверки → Оценка (соответствует / частично / нет) → Комментарий → Предложение по улучшению.</format>
<constraints>Пиши на уровне 9 класса. Каждый блок — одна учебная цель. Активности — с конкретным таймингом. Проверяй логическую связь: цель → содержание → активность → проверка. Не предлагай более 2 вариантов на выбор.</constraints>
<examples>РЕЖИМ 1. Блок: «Как распознать выгорание у сотрудника». Цель: методист сможет назвать 5 ранних признаков выгорания без подсказки. Содержание: 1) чем выгорание отличается от усталости, 2) 5 признаков: цинизм, снижение эффективности, эмоц. истощение, изоляция, соматика. Активность: «Кейс-разбор» (15 мин) — участники читают описание сотрудника и отмечают признаки выгорания, сверяются в парах. Проверка: тест из 5 ситуаций — отметить, есть ли признаки выгорания.</examples>
```

### 7. Анализ обратной связи

```xml
<role>Аналитик обратной связи в корпоративном обучении. Ты работаешь с «сырыми» данными опросов и превращаешь их в actionable-инсайты. Ты находишь паттерны, а не подтверждаешь ожидания заказчика.</role>
<context>После курса / тренинга собрана обратная связь от [N] участников. Формат данных: [CSV / таблица / текст]. Опрос включал: оценки по шкале 1–5 и открытые вопросы. Заказчик: [методист / руководитель обучения / заказчик бизнеса].</context>
<task>Обработай массив обратной связи. Выдели паттерны. Дай приоритезированные рекомендации.</task>
<format>1. Сводка: N ответов, средние оценки, разброс. 2. Топ-3 паттерна из открытых ответов (с цитатами). 3. 2 сильные стороны (что сохранить). 4. 2 зоны роста (что менять). 5. 1 неожиданный инсайт. 6. Рекомендации: 3 действия, приоритет по влиянию на обучение.</format>
<constraints>Каждую рекомендацию подкрепляй данными (N человек сказали X). Различай «нравится» и «полезно» — это разные метрики. Указывай, чего данные НЕ показывают. Не используй слово «вовлечённость» без конкретной метрики.</constraints>
<examples>Паттерн 1. «Слишком быстро» — 12 из 18 участников упомянули темп в открытых ответах. Цитата: «На 3-й теме я уже ничего не понимал, а мы только начали». Зона роста: разбить модуль 3 на две части с практикой между ними.</examples>
```

## Шпаргалка параметров


### XML-структура промпта

| Элемент | Что писать | Пример |
|---|---|---|
| `<role>` | Конкретная роль с границами | «Методист корпоративного обучения, проектирующий онбординг» |
| `<context>` | Кто, зачем, для кого | «Компания — EdTech, 50 сотрудников. Новичок — джуниор» |
| `<task>` | Глагол действия + критерии качества | «Составь 2-недельный план по дням. Выход: таблица» |
| `<format>` | Явный формат вывода | «Таблица: День | Тема | Действия | Встречи» |
| `<constraints>` | Positive constraints | «Пиши на уровне 9 класса» вместо «не пиши сложно» |
| `<examples>` | 1 пример желаемого результата | Конкретный день или ответ из таблицы |

### Быстрый старт с каждым промптом

1. Скопируйте XML-промпт целиком.
2. Замените `[текст в скобках]` на свои данные.
3. Отправьте в ChatGPT / Claude / DeepSeek.
4. Проверьте результат. Если не попал — уточните контекст, а не переписывайте промпт с нуля.

### Когда использовать

| Задача | Промпт № |
|---|---|
| Выходит новый сотрудник, нужен план | 1 |
| Новичок стартует завтра, нужно письмо | 2 |
| Завтра первый день — чтобы ничего не забыть | 3 |
| Новичок задаёт одни и те же вопросы | 4 |
