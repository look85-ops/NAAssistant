# /digest

Производство выпуска дайджеста «Радар L&D»: research → синтез → вёрстка → публикация.

**Канонический формат выпуска: `knowledge/digest-format.md` — читать ПЕРЕД сборкой. Дизайн-голос «Тихая уверенность», структура секций, анти-паттерны — там.**

## Процесс

### 1. Подготовка
- Проверяем Бэклог идей (если есть)
- Фиксируем фокус выпуска
- Номер выпуска: предыдущий + 1

### 2. Research (webfetch, НЕ websearch)
`websearch` не работает (403). Только `webfetch`:
- DDG Lite: `https://lite.duckduckgo.com/lite/?q={query}&num=6` — 1-2 попытки максимум, потом капча
- Прямые источники (надёжнее): Habr (`https://habr.com/ru/news/`), Hacker News (`https://news.ycombinator.com` + Algolia API `https://hn.algolia.com/api/v1/search_by_date?...`), Training Industry, ATD, JetBrains Research, HR Executive
- RU-запросы к DDG Lite иногда проходят — проверять фактом, не априори

Стандартные запросы (адаптировать под тему, EN/RU):
- L&D/корпоративное обучение + год
- learning analytics AI L&D
- instructional design tools
- edtech trends + год
- L&D jobs/HR news (для блока рынок/карьера)

Используем 3-4 параллельных research-агента через `task`: (1) сигналы недели L&D×AI, (2) инструмент недели, (3) рынок/карьера РБ+int, (4) при необходимости — вывод/дизайн.

### 3. Синтез по канону
Структура выпуска (из `knowledge/digest-format.md`):
1. **01 · Карта недели** — 3-4 сигнала с источником и датой
2. **02 · Радар трендов** — статусы тем (появился/усиливается/плато/угасает)
3. **03 · Сквозная мысль** — главный вывод недели (крупная цитата)
4. **04 · Инструмент недели** — ТОЛЬКО инструмент, с привязкой к выводу недели
5. **05 · Рынок/Карьера** — международный фон. Рынок РБ — НЕ публиковать (персонально).

Правила отбора:
- Каждый элемент отвечает на «что с этим делать»
- Один выпуск — одна сквозная тема
- Баланс: не только ИИ — тренды обучения, методики, инструменты
- Все цифры — из источника, без «по оценкам экспертов»
- Ничего непроверенного из веба — иначе блок пропускается

### 4. Пост-райтер (humanizer-правила)
- Запрещён канцелярит: «в рамках», «осуществляется», «представляется возможным», «в целях», «в настоящее время» → короткие глаголы и факты.
- Выжечь AI-клише: «трансформировать бизнес», «вектор развития», «синергия», «unlock potential», «game-changer», «революционный» → убрать или переписать конкретно.
- Убрать пустые связки и tautology: «как уже было сказано выше», «следует отметить, что» → удалить; оставить факт и действие.
- Тест на конкретику: в каждом абзаце цифра, пример или проверяемое утверждение.
- Человеческий язык: писать как говорит человек, не машина.

### 5. Вёрстка
- Собираем `career/posts/digest/digest-{YYYY-MM-DD}.html` по шаблону эталона `career/posts/digest/digest-2026-08-20.html`
- Дизайн-голос «Тихая уверенность»: палитра #F4F0E8/#1E1D1B/#A6332E/#2B3A55, шрифты Literata/Golos Text/JetBrains Mono
- Обложка: мастхед + фор-ум строка «Еженедельный дайджест об обучении, ИИ и карьере. Для L&D-специалистов и HR-руководителей: тренды, инструменты, цифры.»
- OG-теги и canonical-ссылка на GitHub Pages

### 6. Публикация
- Показываем пользователю финальную версию — БЕЗ автопубликации
- После подтверждения — публикуем в LinkedIn/ТГ по факту
- Добавляем задачу на замер метрик через 7 дней

### 7. После публикации
- Обновить реестр тем (для радара трендов следующего выпуска)
- Записать 1-2 инсайта в `knowledge/linkedin-rules.md`
- Добавить строку в `logs/decisions.md`

## Параметры

- `--topic` — тема выпуска (если не указана — выбирается автоматически)
- `--dry-run` — только research, без записи и публикации

## Когда вызывать

- Только по команде пользователя: «выпусти дайджест», «сделай дайджест», `/digest`

## Guardrails

- Не публиковать без подтверждения пользователем
- Если DDG заблокировал — пауза, прямой webfetch к источникам
- Не использовать непроверенные данные — все цифры из источника
