# /checkpoint — сохранение прогресса

Промежуточный снимок состояния задачи. Дополняет `/handoff` — handoff для передачи между агентами/сессиями, checkpoint для фиксации прогресса внутри одной задачи.

## Когда вызывать

- После завершения фазы (см. `/plan`)
- Перед рискованным шагом (чтобы можно было откатить)
- Перед перерывом в работе
- Когда сделано > 50% задачи и нужно зафиксировать

## Что фиксирует

Агент создаёт в `logs/checkpoints/checkpoint-F-NNN-YYYY-MM-DD-HHmm.md`:

```
## Checkpoint: F-NNN — {название задачи}

**Дата:** YYYY-MM-DD HH:MM
**Фаза:** X из Y (по плану)

### Что сделано с прошлого checkpoint
- Артефакт 1
- Артефакт 2

### Что осталось
- Шаг 1
- Шаг 2

### Текущее состояние
- {файлы изменены, ветка, последний коммит}
- {результаты проверок: линт, тесты, smoke}

### Блокеры
{если есть — что мешает}

### Следующий шаг
{конкретное действие для продолжения}
```

## Правила

- Минимум: описание + список сделанного/оставшегося
- Если директории `logs/checkpoints/` нет — создать
- Формат лёгкий, не буквоедский. Цель — не потерять контекст, а не создать документ на 3 страницы.
