# /plan — планирование перед стартом

Структурированное планирование задачи перед `/start-task`. Дополняет `/grill` — grill проясняет неопределённости, plan раскладывает по шагам и оценивает риски.

## Когда вызывать

- Перед любой задачей, которая затрагивает > 3 файлов или > 1 агента
- Когда есть выбор между подходами
- Когда `/start-task` требует разбивки на фазы

## Процесс

Агент формирует план по шаблону:

### 1. Переформулировка задачи
{Что делаем, одной фразой. Зачем, для кого, какой результат.}

### 2. Фазы
{2–5 фаз с подшагами. Каждая фаза — логически завершённый кусок.}

### 3. Зависимости
{Что нужно ДО старта: файлы, данные, решения других агентов/людей.}

### 4. Риски
- 🔴 Критические: что может заблокировать задачу
- 🟡 Средние: что замедлит, но не остановит
- 🟢 Низкие: неприятности, но не фатально

### 5. Pre-Mortem (если уместно)
{3 причины, почему может провалиться + 3 причины пожалеть, если не делать.}

### 6. Оценка
- Сложность: HIGH / MEDIUM / LOW
- Примерное время: часы/дни
- Какие агенты нужны

## Барьер подтверждения

После вывода плана агент спрашивает: «План ок? Начинаем? (да / правки / стоп)»

Без явного «да» — код не пишется, файлы не трогаются.

## Интеграция с workflow

```
/grill → /plan → «да» → /start-task → работа → /checkpoint → ... → /verify → /finish-task
```

## Отличие от /grill

- /grill — допрос Наташи: что именно нужно, границы, критерии
- /plan — раскладка агента: как именно сделать, фазы, риски, оценка
