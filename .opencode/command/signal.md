# /signal

Производство еженедельного брифинга «Сигнал»: research через webfetch (DuckDuckGo Lite) → синтез → файл в `knowledge/signal/`.

## Процесс

### 1. Research (webfetch DuckDuckGo Lite)

Выполняем параллельные запросы через `webfetch` по URL:
```
https://lite.duckduckgo.com/lite/?q={query}&num=6
```

**Важно:** DDG Lite капчит русскоязычные запросы (кириллица). English-запросы проходят стабильно. Поэтому для каждого блока — дублируем на английском.

**Стандартные запросы для 7 блоков** (адаптировать под текущий контекст):

| Блок | Запросы (всегда EN) | Fallback при капче |
|------|---------------------|-------------------|
| L&D/EdTech | `L%26D+corporate+training+2026`, `edtech+news+2026`, `AI+education+2026` | `webfetch` к Training Industry, Habr news |
| AI приземлённый | `AI+tools+practical+2026`, `AI+news+July+2026` | `webfetch` к Hacker News, Habr |
| Рынок/Карьера | `L%26D+jobs+2026`, `HR+trends+2026` | `webfetch` к Habr news (раздел карьера) |
| Минск/Переезд | `Minsk+culture+events+2026`, `Belarus+news+2026` | `webfetch` к новостным сайтам РБ |
| Творчество | `sculpture+exhibition+2026`, `photography+art+2026` | `webfetch` к HN, arts sites |
| Инструмент недели | `best+productivity+tools+2026`, `new+developer+tools+2026` | `webfetch` к DEV.to, Product Hunt |
| Проекты | `open+source+AOS+analytics`, `AI+safety+2026` | `webfetch` к HN, GitHub trending |

Используем 4-5 параллельных запросов за раз (максимум — DDG начинает капчить).

При капче:
- Переключиться на другой запрос того же блока
- Если все DDG запросы каптятся — использовать `webfetch` напрямую к сайтам-источникам: Hacker News (`https://news.ycombinator.com`), Habr (`https://habr.com/ru/news/`), DEV.to (`https://dev.to`)
- Как альтернатива — попробовать `websearch` (может работать в другие дни)

После получения результатов — выборочно `webfetch` 1-2 ключевых статьи для деталей.

### 2. Синтез

Из raw-результатов отбираем по 1-2 сигнала на блок. Формат:
- **Заголовок сигнала** (что произошло)
- **Конкретика** (2-3 строки фактов)
- **Твой вывод** (что с этим делать — 1 строка, жирным)

Правила отбора:
- Только то, что реально повлияет на решения/действия Наташи
- Максимум конкретики, без воды
- Все цифры — из источника
- Если по блоку нет сильных сигналов — пропускаем, не заполняем «воздухом»

### 3. Запись в docx

- Конвертируем .md → .docx через Python: `C:\Users\marcenuk\AppData\Local\Python\pythoncore-3.14-64\python.exe scripts/convert_md_to_docx.py`
- Скрипт `scripts/convert_md_to_docx.py` на вход берёт .md, на выход даёт .docx
- Сохраняем в `knowledge/signal/YYYY-MM-DD.docx`
- Показываем Наташе на подтверждение

### 4. После подтверждения

- Добавить строку в `logs/decisions.md` (ключевые инсайты выпуска)
- Обновить F-003 в бэклоге (дата последнего выпуска)

## Сетка блоков (7)

1. **L&D/EdTech** — новые инструменты, кейсы корпобучения, тренды рынка
2. **AI приземлённый** — что реально применить, не хайп
3. **Рынок/Карьера** — вакансии, тренды найма, зарплаты (РФ, РБ, int)
4. **Минск/Переезд** — события, волонтёрство, курсы, новости РБ
5. **Творчество** — выставки, техники, референсы
6. **Инструмент недели** — 1 конкретный инструмент/приём
7. **Проекты** — сигналы для Амальгаммы, AOS, Бустера, Pin

## Когда вызывать

- Раз в неделю (пн или в зависимости от запроса)
- По команде: «сделай сигнал», «свежий сигнал», `/signal`
