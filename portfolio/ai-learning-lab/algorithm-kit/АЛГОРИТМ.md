# Алгоритм: как ставятся «Слайд №N» и вставляются скрины

## Суть

В сценарии занятия (.docx) расставлены метки «Слайд». Задача — для каждой метки
найти **правильный слайд** в презентации (.pptx), поставить его номер «Слайд №N»
и вставить скриншот слайда в документ (преподаватель видит и текст, и слайд).

Ключевая идея: **номер определяется по текстовому соответствию, а не по порядку**.
Сценарий и презентация идут в одном порядке, поэтому задача сводится к тому,
чтобы выстроить неубывающее отображение «метка → слайд».

## Шаг 1. Render

Экспорт слайдов в PNG (нужен установленный PowerPoint):

```python
import win32com.client
pp = win32com.client.Dispatch('PowerPoint.Application')
pres = pp.Presentations.Open(PPTX, ReadOnly=-1, Untitled=-1, WithWindow=-1)
pres.Slides.Item(n).Export(path, 'PNG', 2500, 1406)
```

Разрешение эталона — **2500×1406** (16:9). Размер скрина в документе —
**5,5 см по высоте**.

## Шаг 2. Match (главное, где раньше всё ломалось)

**TF-IDF** отсекает общие «мусорные» слова («преподаватель», «бесстыковой путь»),
чтобы слайд сопоставлялся по уникальному контенту.

```
idf(t) = ln((N+1)/(df(t)+1)) + 1          # N = число слайдов
vec(слайд)  = TF·IDF по всем текстам слайда
vec(плашка) = TF·IDF по тексту после метки до следующей «Слайд»
sim = косинус(vec(плашка), vec(слайд))
```

Дальше — **монотонное выравнивание** (DTW / Needleman–Wunsch по матрице
сходства): ищем неубывающее отображение метка[i] → слайд[j], максимизирующее
сумму сходства. Это даёт правильную нумерацию даже там, где текста мало.

**Порог уверенности:** ставить номер, только если косинус ≥ ~3. Слабые места
(«Результат шага», заголовки-воды, «анимация по щелчку») оставляем пустыми —
«нет однозначного соответствия → не трогаем».

**Проверка якорей:** 5–9 ключевых заголовков разделов должны лечь 1:1. Если
anchor не сходится — остановиться и разобраться, а не гнать дальше.

## Шаг 3. Insert

- Картинка вставляется **новым абзацем сразу после «Слайд №N»**.
- Абзац копирует оформление плашки (тот же голубой фон `CCECFF`), внутри один
  `<w:r>` с `<w:drawing>`.
- Всё через `lxml` + `zipfile`. Медиа — `word/media/slideNNN.png`, связь —
  `word/_rels/document.xml.rels`.

Размер скрина (16:9, 5,5 см по высоте):
```
wp:extent cx=3519176 cy=1980000
```

## Критичные грабли

1. **Clark-нотация тегов.** В `lxml` итерировать надо `'{uri}p'`, `'{uri}t'`, а
   не `'uri p'` — без фигурных скобок вернёт 0 элементов. Отдельно держать
   `W_URI` (для `xmlns:w="..."`) и `W = '{'+W_URI+'}'` (для lxml).
2. **Не пересохранять через `python-docx.save()`** — только lxml + zipfile.
3. Номера-дубли: если соседние метки дают один слайд — картинку вставлять один раз.
4. При удалении старых картинок **не трогать media, на которые ссылаются
   `header*.xml.rels` / `footer*.xml.rels`** — иначе файл не откроется.

## Очистка сценария перед повторной раскладкой

1. У всех плашек `Слайд №N` → `Слайд` (первый `w:t` → «Слайд», остальные run'ы пустые).
2. Удалить image-абзацы (`<w:p>` с `<wp:inline>`) сразу после плашек.
3. Почистить `document.xml.rels` и `word/media/*` только для висячих ссылок.

## Актуализация после изменения презентации

Когда из .pptx удалили/сдвинули слайды (например 272 → 268):

1. Дифф по заголовкам old vs new — найти **сдвиг**. Как правило это чистое
   удаление: `f(old) = old - k` для всех `old ≥ порог`.
2. Перерендерить новую колоду, пересчитать match заново.
3. Для сдвинутых слайдов контент сохранился — править только текст номера,
   картинка остаётся корректной.
4. Удалённые слайды (на них кто-то ссылался) — показать автору, не угадывать.
5. Формат чисел привести к единому виду (`Слайд №N` или `Слайд N`).

## Правила на будущее

1. Перед стартом — зафиксировать пару файлов (число слайдов, дата).
2. Полная текстовая карта «сценарий ↔ слайды».
3. Вставка только через ZIP/XML.
4. Стоп при первой нестыковке — спросить, а не угадывать.
5. Плотные блоки с одинаковыми слайдами («ВАША ЗАДАЧА», арт-блок) — показать
   варианты автору.
