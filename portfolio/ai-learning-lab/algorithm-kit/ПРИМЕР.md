# Пример: как выглядит правильный результат

Реальный кейс М3Д1 (модуль одинакового формата) — для калибровки, что считать
«верным», а что «ошибкой».

## Вход

- Сценарий `.docx` — таблица «ДЕНЬ 1», колонка «Подробное описание», внутри
  метки «Слайд».
- Презентация `.pptx` — 272 слайда.

## Что должен сделать агент (шаг за шагом, на реальных числах)

### Match — якоря легли 1:1

| Метка в сценарии | Номер слайда | Заголовок слайда |
|---|---|---|
| «Мы переходим к теме: Укладка…» | 43 | УКЛАДКА БЕССТЫКОВОГО ПУТИ |
| «Маркировка рельсовых плетей» | 103 | МАРКИРОВКА РЕЛЬСОВЫХ ПЛЕТЕЙ |
| «Текущее содержание…» | 124 | ТЕКУЩЕЕ СОДЕРЖАНИЕ И ПРОМЕЖУТОЧНЫЕ РЕМОНТЫ |
| «Контроль за угоном плетей» | 148 | КОНТРОЛЬ ЗА УГОНОМ ПЛЕТЕЙ |
| «Разрядка температурных напряжений» | 188 | РАЗРЯДКА ТЕМПЕРАТУРНЫХ НАПРЯЖЕНИЙ |
| «Принудительный ввод плетей…» | 217 | ПРИНУДИТЕЛЬНЫЙ ВВОД ПЛЕТЕЙ… |
| «Бесстыковой путь из старогодных» | 251 | БЕССТЫКОВОЙ ПУТЬ ИЗ СТАРОГОДНЫХ МАТЕРИАЛОВ |

Если эти семь легли верно — сопоставление в целом корректно.

### Итог на М3Д1

- **235 плашек** → номер + скрин.
- **41 плашка** оставлена без номера: вступление (титул), служебные строки
  («Преподаватель:», «Результат шага», «Рабочие тетради…»), плотные блоки
  одинаковых слайдов («анимация по щелчку», температурные таблицы).
- Номера 1…271, монотонно, каждый ведёт на верный слайд.

## Как проверить, что номер верный

Открыть сценарий, найти «Слайд №43», посмотреть абзац выше — там «переходим к
теме „Укладка бесстыкового пути“». Открыть презентацию, слайд 43 — «УКЛАДКА
БЕССТЫКОВОГО ПУТИ». Совпало → верно.

## Примеры ошибок (как НЕ должно быть)

| Что видно | Диагноз |
|---|---|
| «Слайд №1615» | число разъехалось по run'ам («№16» + «15»): агент резал текст по кускам, не собрал run'ы |
| номера 20 → 9 → 21 | нет монотонности: агент ставил по счётчику/угадывал, а не выравниванием |
| скрин под «Слайд №43» показывает «СКРЕПЛЕНИЯ» | картинка не совпала с номером |
| файл не открывается | удалили media, на который ссылается footer/header |
| «Слайд №273» при 268 слайдах | сдвиг презентации не пересчитан после удаления слайдов |

## Чем это отличается от старого (битого) подхода

- Старый: первый маркер → слайд 1, второй → 2, … и пересохранение через
  `python-docx.save` (ломал выравнивание).
- Новый: номер по текстовому совпадению + выравнивание, вставка через
  XML/ZIP. Поэтому и отрабатывает стабильно.
