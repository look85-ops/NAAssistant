Урок 2. Git: версионирование и первый коммит

**Модуль 1:** · **Время:**

Модуль 1: Технический минимум: читать, понимать, коммитить Неделя: 2 из 3 Время: 2–2.5 ч

1. Цель недели

Зачем это L&D-специалисту в работе с AI.

Все ваши AI-артефакты (промпты, схемы агентов, скрипты, датасеты для fine-tuning) живут в файлах. Git — это машина времени для этих файлов. Вы можете откатиться к любой версии, посмотреть, что изменилось, и не бояться «а вдруг я всё сломаю». Без Git любая серьёзная работа с AI-инструментами превращается в кашу из файлов финальная_версия_окончательная_v2.py.

К концу этого урока вы создадите свой первый репозиторий, сделаете коммит, зальёте код на GitHub — и поймёте, почему разработчики не работают без этой системы.

2. Теория

Что такое Git

Git — это система контроля версий. Она записывает слепки всех изменений в ваших файлах. Каждый слепок = коммит (commit). Вы можете в любой момент вернуться к любому коммиту, посмотреть, что изменилось, и даже разветвить историю.

Представьте, что вы пишете курсовую: - Версия 1: набросок - Версия 2: добавили главу - Версия 3: переписали введение - Версия 4: поняли, что старое введение было лучше → вернулись к версии 2

Без Git вы храните 4 файла: курсовая_v1.docx, курсовая_v2.docx... С Git у вас один файл и 4 коммита. Вы переключаетесь между ними одной командой.

Репозиторий

Репозиторий (repo) — это папка, за которой Git следит. Внутри неё есть скрытая папка .git — там хранится вся история. Вы её не трогаете, Git сам с ней работает.

Основные понятия

  • commit (коммит) — сохранённый слепок всех файлов в папке. У каждого коммита есть сообщение (что изменили), автор, дата и уникальный хеш (длинный набор букв и цифр).
  • ветка (branch) — отдельная линия разработки. По умолчанию вы в ветке main (или master). Можно создать отдельную ветку для эксперимента, поработать в ней, а потом влить обратно в main.
  • локальный репозиторий — на вашем компьютере.
  • удалённый репозиторий (remote) — на GitHub. Это как бэкап + возможность работать с другими.
  • push — отправить ваши коммиты на GitHub.
  • pull — скачать чужие коммиты с GitHub.

Жизненный цикл файла в Git

У файла три состояния: 1. Untracked — Git не знает про этот файл (вы его только создали). 2. Staged (индексирован) — вы сказали Git: «этот файл хочу сохранить в следующем коммите». Команда git add. 3. Committed (сохранён) — вы сделали слепок. Команда git commit.

Схема:

Working Directory  →  Staging Area  →  Repository
      git add               git commit

GitHub — это не Git

Git — программа на вашем компьютере. GitHub — сайт, где хранятся удалённые репозитории. Можно работать и без GitHub (только локально), но для бэкапа и коллаборации он нужен.

3. Шпаргалка (сохраните себе)

Этот урок вы будете почти полностью выполнять в терминале. Git-команды выглядят как git что-то. Проверьте, что Git установлен:

git --version

Если Git не установлен — скачайте с https://git-scm.com/downloads (установка: везде «Далее», ничего не меняйте). После установки перезапустите PowerShell.

Основные команды

Действие Команда
Создать репозиторий в текущей папке git init
Проверить статус файлов git status
Добавить файл в staging git add имя_файла
Добавить все файлы git add .
Сделать коммит git commit -m "сообщение"
Посмотреть историю git log
Посмотреть историю (кратко) git log --oneline
Увидеть изменения git diff

Первичная настройка (один раз)

Перед первым коммитом нужно представиться:

git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта.ru"

Работа с GitHub

Действие Команда
Связать локальный репозиторий с удалённым git remote add origin https://github.com/ваш-логин/название-репозитория.git
Отправить коммиты на GitHub git push -u origin main
Забрать изменения с GitHub git pull
Посмотреть, с каким удалённым репозиторием связана папка git remote -v

4. Практика

Все упражнения выполняйте в PowerShell (который вы освоили на прошлой неделе).

Упражнение 1. Проверка Git и настройка (10 мин)

Откройте PowerShell. Проверьте, установлен ли Git:

git --version

Если видите номер версии — отлично. Если ошибка «не является командой» — Git не установлен. Скачайте с https://git-scm.com/downloads и установите.

Теперь представьтесь (сделайте один раз, Git запомнит):

git config --global user.name "Ваше Имя"
git config --global user.email "ваша@почта.ru"

Упражнение 2. Первый репозиторий (15 мин)

Создайте новую папку для эксперимента:

mkdir C:\Users\ИмяПользователя\Desktop\my-first-repo
cd C:\Users\ИмяПользователя\Desktop\my-first-repo

Теперь сделайте эту папку репозиторием:

git init

Git ответит: Initialized empty Git repository in .... Проверьте:

git status

Вы увидите: On branch main и nothing to commit. Репозиторий пуст.

Упражнение 3. Первый коммит (15 мин)

Создайте файл readme.md (через терминал, как на прошлом уроке):

ni readme.md

Откройте его в любом редакторе и напишите:

# my-first-repo

Мой первый репозиторий. Учусь работать с Git.

Сохраните файл. Проверьте статус:

git status

Git скажет, что есть untracked file — файл, за которым Git ещё не следит. Добавьте его:

git add readme.md

Проверьте статус снова:

git status

Файл перешёл в состояние staged (зелёным цветом). Теперь сделайте коммит:

git commit -m "Первый коммит: readme"

Вы увидите что-то вроде:

1 file changed, 3 insertions(+)
create mode 100644 readme.md

Поздравляю. Только что вы сделали свой первый коммит. Посмотрите историю:

git log --oneline

Вы увидите одну строчку — ваш первый коммит.

Упражнение 4. Второй коммит: меняем файл (10 мин)

Откройте readme.md в редакторе и допишите строку:

## Как я учусь

Прохожу курс L&D × AI. На этой неделе осваиваю Git.

Сохраните. Проверьте статус:

git status

Файл изменился — Git это видит. Посмотрите, что именно изменилось:

git diff readme.md

Git покажет добавленные строки (они будут зелёными со знаком +). Теперь сохраните изменения:

git add readme.md
git commit -m "Добавил раздел Как я учусь"

Посмотрите историю:

git log --oneline

Теперь два коммита. Обратите внимание: у каждого свой хеш — короткий идентификатор (например, a1b2c3d).

Упражнение 5. Возврат к предыдущей версии (10 мин)

Git позволяет вернуться к любому коммиту. Посмотрите историю с полными хешами:

git log

Скопируйте хеш первого коммита (он самый нижний). Вернитесь к нему:

git checkout <хеш>

Файл readme.md теперь снова содержит только первую версию — Git откатил состояние. Вернитесь обратно к последней версии:

git checkout main

Файл снова полный. Git работает как машина времени.

Упражнение 6. Ветки (15 мин)

Создайте новую ветку для эксперимента:

git branch experiment

Проверьте, какие ветки есть:

git branch

Ветка main выделена звёздочкой (* main). Переключитесь на новую ветку:

git checkout experiment

Теперь вы в ветке experiment. Откройте readme.md и допишите строку:

## Эксперимент

Это изменение я делаю в отдельной ветке.

Сохраните, закоммитьте:

git add .
git commit -m "Эксперимент в отдельной ветке"

Вернитесь в main:

git checkout main

Файл снова без экспериментальной строки. Ветки не мешают друг другу. Теперь влейте эксперимент в main:

git merge experiment

Файл обновился — строка из ветки experiment появилась в main.

Посмотрите историю — теперь видно, что была развилка:

git log --oneline

Упражнение 7. Gitignore (10 мин)

Бывают файлы, которые не нужно сохранять в Git: временные, служебные, с паролями. Для этого есть файл .gitignore.

Создайте два файла:

ni secret.txt
ni notes.txt

Добавьте запись в secret.txt: это секрет. Теперь создайте файл .gitignore:

ni .gitignore

Откройте .gitignore в редакторе и напишите:

secret.txt

Сохраните. Проверьте статус:

git status

secret.txt исчез из списка — Git его игнорирует. notes.txt всё ещё на месте. Закоммитьте .gitignore:

git add .gitignore
git commit -m "Добавил gitignore, скрыл secret.txt"

Упражнение 8. GitHub: локальный → удалённый (25 мин)

Это упражнение требует аккаунта на GitHub. Если его нет — зарегистрируйтесь на github.com (бесплатно).

  1. Зайдите на github.com, нажмите зелёную кнопку New (создать новый репозиторий).
  2. Введите название: my-first-repo (как ваша локальная папка).
  3. Оставьте Public, не ставьте галочку «Add a README» (у вас уже есть).
  4. Нажмите Create repository.

GitHub покажет вам команды. Найдите строку:

git remote add origin https://github.com/ваш-логин/my-first-repo.git

Скопируйте и выполните в PowerShell (в папке my-first-repo):

git remote add origin https://github.com/ваш-логин/my-first-repo.git

Проверьте:

git remote -v

Теперь отправьте ваши коммиты на GitHub:

git push -u origin main

PowerShell запросит логин и пароль GitHub. Введите: - Логин: ваш email на GitHub - Пароль: не обычный пароль, а Personal Access Token (если его нет — создайте в GitHub: Settings → Developer settings → Personal access tokens → Tokens (classic) → Generate new token, поставьте галочку repo, скопируйте токен и сохраните).

После успешного пуша обновите страницу репозитория на GitHub — вы увидите ваши файлы и историю коммитов.

Упражнение 9. Создание артефакта (10 мин)

Создайте файл с историей ваших коммитов:

cd C:\Users\ИмяПользователя\Desktop\ваш-проект
mkdir career
git log --oneline > career\git-demo.md

Откройте career\git-demo.md в редакторе. Вы увидите список коммитов. Допишите в начало три предложения:

# Git-демо: мой первый опыт

**Дата:** [дата]
**Что делала:** создала репозиторий, сделала несколько коммитов, поработала с ветками, отправила на GitHub.

## Лог коммитов

Сохраните. Теперь закоммитьте артефакт в ваш основной проект, а не в экспериментальный репозиторий.

5. Рефлексия (напишите мне)

  1. Сколько времени заняло?
  2. Что было самым непонятным в Git?
  3. Что было самым полезным?
  4. Оценка материала от 1 до 5

6. Чек-лист готовности

  • [ ] Проверили Git: git --version вернула номер
  • [ ] Создали локальный репозиторий (git init)
  • [ ] Сделали минимум 2 коммита с разными сообщениями
  • [ ] Создали и слили ветку (git branch, git merge)
  • [ ] Настроили .gitignore
  • [ ] Создали репозиторий на GitHub и запушили коммиты (git push)
  • [ ] Создали артефакт career/git-demo.md с логом коммитов

7. Артефакт

В вашем проекте должен появиться файл:

ваш-проект/
└── career/
    └── git-demo.md          # Лог коммитов + описание опыта

Также на GitHub появится публичный репозиторий my-first-repo с историей ваших коммитов.

8. Что дальше

На следующей неделе — API и чтение кода. Вы научитесь делать запросы к AI-моделям через терминал, читать документацию API и понимать, что происходит в чужом коде.

Но сначала закрепите Git. Сделайте ещё пару коммитов в свой основной проект — хотя бы по одному на каждый день. Git становится полезным, когда вы входите в привычку коммитить часто.

Шутка дня (Git-сага)

Представьте: отдел L&D целый год пишет курс. Без Git. Версии файлов называются: курс.docx, курс_итог.docx, курс_окончательный.docx, курс_реально_последний.docx, курс_удали_всё_прежнее.docx, курс_нет_это_финал.docx. Пришёл новый руководитель и спросил: «А где тут версия, которую утверждали в марте?» — тишина.

С Git это выглядит так: git log --oneline — и вы видите всю историю. `git checkout <хеш> — и вы в марте. Git не даёт вам врать самому себе про «финальную версию».

Пасхалка: если кто-то скажет «Git — это сложно», напомните эту историю про курс.docx. 😄

Дополнительно (необязательно, но полезно)

  • git log --graph — показывает историю в виде графа (наглядно видны ветки)
  • git commit --amend — исправить сообщение последнего коммита (если ошиблись)
  • git reset HEAD readme.md — убрать файл из staging (если случайно добавили)
  • Попробуйте ввести в терминале git lol — если Git ругнётся, значит, это не настоящая команда, а байка. Настоящие гики делают себе алиас git lol для красивого лога. Хотите — сделайте: git config --global alias.lol "log --oneline --graph --all", и команда git lol заработает.
  • Прочитайте первые 3 раздела книги Pro Git на русском: https://git-scm.com/book/ru/v2
