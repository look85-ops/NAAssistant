# Клонирование слайдов с типовыми донорами (М4Д2)

**Дата:** 2026-08-17 · **Фаза A М4Д2** · **ref:** Управляющая_презентация_М4Д2_fin.pptx

## Правило
Когда в сценарии много bare-маркеров без номера («Слайд», «Слайд №N» нет), подбирай донора **по типу контента**, а не по ключевым словам:

| Тип маркера | Донор | Комментарий |
|---|---|---|
| SELFWORK (сам. работа) | слайд «Самостоятельная работа» (55) | 4 строки: заголовок/подгруппы/тетрадь/время |
| QUESTION / Блиц | слайд-вопрос «Модуль 1.» (20/22/47) | 2 строки: шапка + текст вопроса |
| DISCUSS | слайд «Дискуссия» (156) | шапка + 4–6 вопросов |
| CONTENT | киword-донор по тексту (weak) | часто «НЕ ляжет» — править вручную |

## Выбор донора для CONTENT: «просторный и простой» (правило от Наташи, 2026-08-17)
- Для контентных слайдов выбирай **максимально просторные и простые** слайды-доноры (референс — слайд 19 fin-версии): минимум текста, много воздуха, крупные блоки. Их легче править вручную при несовпадении строк — экономит время.
- Избегай плотных слайдов с десятком мелких строк: при замене текста они разъезжаются, и ручная правка съедает часы.
- Практика Наташи: она прошлась по клонам и заменила сложные доноры на простые сама. Для М4Д4 сразу фильтровать доноров по «простоте» (число строк в texts), а не только по типу.

## Правда о контентных слайдах (М4Д4, новый дизайн М1Д1 — 2026-08-18)
- **Провал №1:** контентные слайды — это не «Title + список». Это целые композиции: картинка + подписи, схемы/таблицы, тёмные блоки, сгруппированные фигуры. Простое клонирование «общего» макета + замена текста **не срабатывает** — контент разъезжается, теряется смысловая структура.
- **Работает:** титул, разделы (Перебивочный), правила, регламент, перерыв/обед, вопросы, итоги — лёгкие текстовые макеты. Клонирование их + замена текста — ок.
- **Вывод для будущего:** контентные слайды в новом дизайне собирать **вручную по одному** или тянуть контент из старой презентации слайд-в-слайд (правильные соответствия макетов), а не «общим» клоном. Это гибрид: каркас (легкие типы) автоматизируется, контент — ручной труд.

## Гибрид 2.0 — проверен, остановились (М4Д4, новый дизайн — 2026-08-19, финал)
- **Технически масштабирование сработало:** координаты вставленных групп совпали с источником до сотой дюйма (слайды 2 и 13 пилота). Но **по визуальной оценке Наташи контент снова не лёг** — группы тащат свои заливки/рамки/тёмные блоки старого дизайна, получается «старый контент на новом каркасе», а не М1Д1.
- **Решение:** НА ЭТОМ ОСТАНОВИЛИСЬ. Все автоматические пути переодеть контентные слайды в новый дизайн исчерпаны.
- **Проверенные и закрытые пути (НЕ работают):** ① клонирование донора + замена текста (композиции разъезжаются); ② `ApplyTemplate` (не переносит макеты — дизайн М1Д1 в фигурах слайдов, не в макетах); ③ гибрид Copy/Paste из 1440-пространства (смещение); ④ гибрид 2.0 (масштаб + Copy/Paste 1:1 — координаты верны, но дизайн не тот); ⑤ Aspose `AddClone` (не переодевает); ⑥ LibreOffice UNO (кросс-документный перенос отсутствует).
- **Вывод:** контентные слайды в новый дизайн М1Д1 переносятся только **вручную** (пересборка композиций в новом макете). Автоматизировать можно только каркас: титул, разделы, правила, регламент, перерывы, вопросы, итоги — лёгкие типы клонируются + замена текста отлично.
- **Что оставлено в работе:** `Управляющая_презентация_М4Д4_новый_дизайн.pptx` (77 слайдов, каркас в новом дизайне) — контентные слайды в нём заполнять вручную.

## Тех. находки
- **Позиционная замена строк** (donor[i] → scenario[i]) надёжна только для типовых шаблонов. Уникальный контент почти всегда требует ручной правки.
- **Заглушки** (ролик/пустое): бери EMPTY-слайд, ставь метку «Новый», контент впишет человек. Не трать на это клонов с заменой.
- **Симуляция позиций обязательна**: duplicate_slide кладёт клон сразу после донора; при многоразовом клонировании одного донора предыдущие клоны сдвигаются. Вычисляй финальный deck, а не позицию в момент вставки. Иначе hides/layout промахнутся.
- Проверка: после update → catalog заново → одиночные совпадения по уникальной строке сценария (первая строка TXT). «Пустые» существующие слайды (EMPTY, фото/схемы) — это норма, не ошибка.
