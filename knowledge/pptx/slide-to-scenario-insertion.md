# Вставка слайдов презентации в сценарий .docx

## Суть задачи

Есть сценарий занятия (.docx) и управляющая презентация (.pptx). В сценарии расставлены метки «Слайд» — в этих местах нужно вставить скриншоты соответствующих слайдов из презентации. Преподаватель видит и текст сценария, и слайды — так удобнее работать с материалом и группой.

## Структура сценария

Сценарий — это .docx с таблицами:
- **Table 0**: титул (программа, модуль, день)
- **Table 1**: карточка тематического блока
- **Table 2**: подготовка преподавателя
- **Table 3**: основной сценарий Дня 1 (столбцы: № шага, Время, Продолжительность, Активность, Подробное описание, Материалы)
- **Table 4**: продолжение сценария (разделы 2+)
- **Table 5+**: приложения

Метки «Слайд» находятся в **столбце C4** (индекс 4, «Подробное описание активности»). Это пятый столбец таблицы.

## Типы меток

| Текст метки | Значение |
|---|---|
| `Слайд` | Безымянная — вставить следующий по порядку слайд |
| `Слайд №X` | Явный номер — вставить слайд X |
| `переход на следующий слайд` и т.п. | **НЕ метка** — нарративный текст, пропускать |

Регулярка для поиска меток: `^Слайд(\s*№\s*\d+)?\s*$`

## Принцип вставки

1. Слайды вставляются **последовательно**: первая метка → слайд 1, вторая → слайд 2, и т.д.
2. Изображение вставляется **сразу после абзаца с меткой**, новым абзацем.
3. Размер изображения: **8.8 × 5.5 см**, выравнивание по центру.
4. Если метка уже имеет изображение после себя — она пропускается (уже обработана).

## Скрипт

**Файл:** `scripts/insert_slides_batch.py`

**Конфигурация** (править в начале файла):
```python
DOCX = r'путь\к\сценарию.docx'      # исходный .docx
OUT = r'путь\к\результату.docx'    # куда сохранить (можно тот же — перезапишет)
PPTX = r'путь\к\презентации.pptx'  # исходная .pptx
TDIR = r'путь\для\png_слайдов'     # папка для экспортированных PNG
START, END = 66, 85                # диапазон слайдов
W, H = 8.8, 5.5                    # размер в см
```

**Запуск:**
```powershell
& "C:\Users\marcenuk\AppData\Local\Python\bin\python.exe" scripts\insert_slides_batch.py
```

**Важно:** используется Python из `C:\Users\marcenuk\AppData\Local\Python\bin\python.exe` (не из WindowsApps — тот не работает в PowerShell).

## Что делает скрипт

1. **Экспорт слайдов** из .pptx в PNG через COM PowerPoint (win32com)
2. **Поиск свободных меток** в .docx — метки «Слайд», после которых НЕТ изображения
3. **Вставка изображений** в XML документа — добавляет новый `<w:p>` с картинкой после метки
4. Сохраняет результат

## Ключевые технические находки

### 1. Нельзя искать метки по тексту — будет коллизия
В одной ячейке десятки меток с одинаковым текстом «Слайд». Поиск через `text_to_elem[text]` всегда возвращает первую. Решение: сохранять **прямую ссылку на lxml-элемент** (`p_elem`) при первом проходе и использовать её при вставке.

### 2. Вставка — от конца к началу
Внутри одной ячейки метки обрабатываются в **обратном порядке позиций** (reverse). Это гарантирует, что вставка нового элемента после маркера не ломает позиции ещё не обработанных маркеров.

### 3. Ячейки — в обратном порядке
Сами ячейки обрабатываются в порядке `sorted(cells, reverse=True)` — чтобы модификации в одной ячейке не влияли на lxml-элементы других ячеек.

### 4. Определение «есть ли изображение после метки»
```python
has_img = (pi + 1 < len(paragraphs)) and (
    paragraphs[pi + 1].findall('.//{wp}inline') or
    paragraphs[pi + 1].findall('.//{a}blip'))
```
Проверяется **следующий параграф** после метки. Если в нём есть `<wp:inline>` (drawing) или `<a:blip>` (image reference) — метка занята.

### 5. COM PowerPoint для экспорта
```python
import win32com.client
pp = win32com.client.Dispatch('PowerPoint.Application')
pp.Visible = True  # обязательно для Export
prs = pp.Presentations.Open(path, WithWindow=False)
prs.Slides(n).Export(out_path, 'PNG')
prs.Close()
pp.Quit()
```
Без `pp.Visible = True` метод `Export` не работает.

### 6. Кодировка в PowerShell
Вывод кириллицы в PowerShell — кракозябры. Результаты проверок писать в UTF-8 файлы и читать их.

## Workflow для одного сценария

1. Получить от Наташи: `.docx` сценария и `.pptx` презентации
2. Убедиться, что в сценарии расставлены метки «Слайд»
3. Узнать, сколько слайдов уже вставлено (если частично)
4. Настроить `START, END` в скрипте
5. Запустить батчами по 20-40 слайдов
6. После каждого батча — Наташа проверяет, при необходимости корректирует нумерацию меток
7. Повторять до конца

## Расхождение числа меток и слайдов

Количество меток «Слайд» и количество слайдов в презентации могут не совпадать:
- Дизайнер мог разбить слайд на несколько (анимация → отдельные слайды) или объединить
- Разница обычно ≤ 15 слайдов

Когда метки заканчиваются раньше слайдов — оставшиеся слайды добавить в конец документа отдельным списком.

## Уроки М1Д4 — провал автоматической вставки (2026-09-07)

**Что пошло не так:** ассистент пытался вставить слайды 41–60 в сценарий М1Д4 — четыре подхода, каждый раз неверно. Финально Наташа вставила все слайды вручную за ≈3,5 ч.

**Корневые ошибки ассистента:**

1. **Не делал карту текстового соответствия до вставки.** Модель вставляла слайды последовательно (маркер N → слайд N+1), игнорируя, что часть слайдов — разложенная анимация (один фрагмент сценария → несколько последовательных слайдов), а часть не имеет маркеров вообще. Нужно: для каждого смыслового блока сценария найти все соответствующие слайды по тексту, а не по порядковому номеру.

2. **Не фиксировал manifest входной пары.** После ручных правок Наташи (удаление дублей, перестановка слайдов 10/11) ассистент продолжал использовать старые номера и старые PNG. Нужно: хэши, число слайдов, дата модификации — до начала работы.

3. **Пересохранял весь DOCX через python-docx**, что ломало форматирование уже проверенных слайдов (выравнивание, нумерация). Нужно: добавлять только новые изображения через прямой XML/ZIP, не трогая существующие параграфы.

4. **Не останавливался при первой нестыковке.** Вместо вопроса Наташе продолжал пересобирать заново, теряя время. Нужно: стоп-критерий — если текстовое соответствие неоднозначно, показать варианты и запросить решение.

**Что сработало (правильные паттерны, применённые в итоге):**
- Текстовое сопоставление слайда с контекстом сценария (а не с номером)
- Вставка от конца блока (внутри одного смыслового фрагмента)
- Групповая вставка: несколько слайдов подряд у одного маркера (анимация/дискуссия)
- Проверка через Word COM (фактическое отображение), а не только XML

**Правило на будущее:**

> Для фазы Б любого модуля: ① manifest пары файлов; ② полная текстовая карта «сценарий ↔ слайды» (все смысловые блоки, включая группы); ③ карта на подтверждение Наташе; ④ вставка только через ZIP/XML (не python-docx.save); ⑤ проверка через Word COM; ⑥ стоп при нестыковке.

**Вывод:** ручная работа Наташи надёжнее автоматической, когда mapping неоднозначен. Автоматизация оправдана только на линейных участках сценария, где 1 маркер → 1 слайд.
