# Автоматическая нумерация «Слайд №N» и вставка скринов в сценарий

> **Это каноничный принцип для новых диалогов.** Когда задача — «расставь
> слайды по сценарию / вставь скрины / исправь нумерацию после изменения
> презентации» — делать через этот пайплайн, а не старые COM-скрипты.

Рабочий алгоритм, который стабильно отрабатывает (М3Д1, М3Д4) там, где раньше
(M1Д4) проваливалась старая логика «маркер №N → слайд №N по порядку» и
COM-скрипты добавления/удаления слайдов.

Ядро: номера ставятся по **текстовому соответствию**, вставка — только через
прямой XML/ZIP. Три шага: Render → Match → Insert.

## Когда применять

- Нужно расставить «Слайд №N» в сценарии .docx по управляющей презентации .pptx.
- Или презентацию изменили (удалили/сдвинули слайды) и надо **пересчитать
  нумерацию** в сценарии.

## Пайплайн

1. **Render** — экспорт слайдов .pptx в PNG через COM PowerPoint (2500×1406, 16:9).
2. **Match** — TF-IDF-косинус + монотонное выравнивание (DTW) «плашка ↔ слайд».
3. **Insert/Update** — правка номеров и вставка картинок через `lxml` + `zipfile`
   (НЕ `python-docx.save` — ломает форматирование).

## 1. Render (PowerPoint COM)

```python
import win32com.client
pp = win32com.client.Dispatch('PowerPoint.Application')
pres = pp.Presentations.Open(PPTX, ReadOnly=-1, Untitled=-1, WithWindow=-1)
pres.Slides.Item(n).Export(path, 'PNG', 2500, 1406)   # 2500×1406 — как в М1Д1
```

- Разрешение эталона М1Д1: **2500×1406** (PNG ~1–2 МБ).
- Слайды М3Д1 — 16:9 (20320000×11430000 EMU).

## 2. Match (ключевой шаг — где была ошибка М1Д4)

TF-IDF отсекает «мусорные» общие слова («бесстыковой путь», «преподаватель»),
чтобы слайд сопоставлялся по **уникальному** контенту, а не по заголовку-воде.

```python
idf(t) = ln((N+1)/(df(t)+1)) + 1     # N = число слайдов
vec(слайд) = TF·IDF по всем `a:t` слайда
vec(плашка) = TF·IDF по тексту после метки до следующей «Слайд»
sim = косинус(vec(плашка), vec(слайд))
```

Затем **монотонное выравнивание** (алгоритм DTW / Needleman–Wunsch по матрице
сходства): сценарий и презентация идут в одном порядке, поэтому ищем
неубывающее отображение плашка[i] → слайд[j], максимизирующее сумму сходства.
Это даёт правильную нумерацию даже там, где текстов мало.

**Порог уверенности:** вставлять номер только если косинус ≥ ~3 (общие маркеры
типа «Результат шага»/заголовки-воды остаются пустыми — по правилу
«нет соответствия → не трогаем»).

**Проверка якорей:** 5–9 ключевых заголовков разделов («УКЛАДКА»,
«МАРКИРОВКА», «РАЗРЯДКА», …) должны лечь 1:1. Если anchor не сходится — стоп.

## 3. Insert

- Картинка вставляется **новым `<w:p>` сразу после абзаца «Слайд №N»**.
- `<w:p>` копирует `pPr` плашки (тот же светло-голубой фон `CCECFF`), внутри
  один `<w:r>` с `<w:drawing>`:
  - **размер скрина — 5,5 см по высоте** (`wp:extent cx=3519176 cy=1980000`,
    16:9 ≈ 9.78×5.5 см, как первый скрин в сценарии М1Д1).
  - `<pic:blipFill><a:blip r:embed="rId"><a:stretch><a:fillRect/></...>`
- Медиа — `word/media/slideNNN.png`, связь — в `word/_rels/document.xml.rels`.
- PNG content-type уже объявлен (если в исходнике были картинки). Если исходник
  их не имел — добавить `<Default Extension="png" ContentType="image/png"/>`
  в `[Content_Types].xml`.

### Критичные грабли

1. **Clark-нотация имён тегов.** В lxml итерировать надо `'{uri}p'`, `'{uri}t'`,
   а не `'uri p'`. Без фигурных скобок `root.iter('http://...p')` вернёт **0**.
   Отдельно держать: `W_URI` (для `xmlns:w="..."`) и `W = '{'+W_URI+'}'` (для lxml).
2. **Не пересохранять через python-docx** — только `lxml` на `document.xml` +
   `zipfile` перепаковка.
3. Номера-дубли: если соседние плашки дают один слайд — картинку вставлять один раз.
4. При удалении картинок из docx **не трогать media, на которые ссылаются
   `footer*.xml.rels` / `header*.xml.rels`** — иначе файл не откроется. Сначала
   собрать ссылки из ВСЕХ `.rels`, не только `document.xml.rels`.

## Очистка сценария (убрать старые номера и скрины)

Перед повторной раскладкой «с нуля»:

1. У всех плашек `Слайд №N` → `Слайд`, числа и суффиксы стереть (первый `w:t`
   → «Слайд», остальные run'ы — пустые).
2. Удалить image-абзацы (`<w:p>` с `<wp:inline>`) сразу после каждой плашки.
3. Почистить `document.xml.rels` и `word/media/*` **только для висячих** ссылок
   (не достижимых ни из одного `.rels`) — иначе ломается колонтитул/шапка.

## Актуализация после изменения презентации

Когда из .pptx удалили/сдвинули слайды (например 272 → 268):

1. Дифф по заголовкам old vs new — найти **сдвиг**. Как правило это чистое
   удаление: `f(old) = old - k` для всех `old ≥ порог`, а удалённые номера
   выпадают.
2. Перерендерить **новую** колоду.
3. Пересчитать match заново (текст мог измениться).
4. Для сдвинутых слайдов контент **сохранился** — править только текст номера
   («Слайд №20» → «Слайд №16»), картинка остаётся корректной (сохранена прежняя).
5. Удалённые слайды (сослались на них) — показать Наташе, не угадывать.
6. Формат чисел в сценарии привести к одному виду (`Слайд №N` или `Слайд N`),
   ручные правки автора бывают без «№».

## Итог на М3Д1 / М3Д4

- М3Д1: 235 плашек → номер + скрин; 41 осталась пустой (плотные блоки таблиц
  без различимого текста, «анимация по щелчку», служебные строки).
- М3Д4: 111 плашек → 109 слайдов, монотонно, скрины 5,5 см. 3 дубля на
  плотных блоках («ВАША ЗАДАЧА», арт-блок) — показаны Наташе, не угаданы.
- Проверка: все номера монотонны, каждый `Слайд №N → media/slideNNN.png`, 0
  рассинхронов; файл открывается.
