# Извлечённые уроки процессов

## Workflow с docx: копия → правки
(F-000) Перед любым редактированием docx через python-docx — сначала сделать копию файла в той же папке. После save проверять размер: если файл вырос > 2x — коррупция, откатываться на копию. Никогда не редактировать единственный экземпляр.

## Research-пайплайн: webfetch к DDG Lite работает, websearch — нет
(2026-07-22) Инструмент `websearch` (search.parallel.ai) стабильно отдаёт 403 (заблокирован). Рабочая альтернатива — `webfetch` к DuckDuckGo Lite: `https://lite.duckduckgo.com/lite/?q={query}&num=6`. 
- English-запросы: проходят стабильно
- RU-запросы (кириллица): DDG Lite капчит почти сразу
- Fallback при капче: `webfetch` напрямую к Hacker News, Habr, DEV.to
- Для Сигнала: все запросы дублировать на английском, RU-блоки (Минск, рынок РФ) — через прямой webfetch к новостным сайтам
Зафиксировано в `.opencode/command/signal.md`.

## Amalgamma: цикл каждый час, не 12ч
(2026-07-24) В `core/constraints.md` было написано «цикл: каждые 12 часов» — ошибка. Фактический cron в GitHub Actions: `0 * * * *` (каждый час). Исправлено в constraints.md. При проверке в AGENTS.md и документации опираться на YAML, не на constraints.

## Полная инвентаризация перед запуском роя
(2026-07-27) Прежде чем запускать рой агентов на задачу, нужно иметь актуальную карту всех проектов. Без неё агенты не видят полной картины и могут давать рекомендации вслепую. Формат карты: GitHub-репозитории, локальные проекты, внешние, связи между ними. Зафиксировано в `docs/projects/PROJECTS_MAP.md`.

## Оркестровка роя: параллельные агенты через task
(2026-07-27) При сложных задачах (стратегия, сценарии, проверка идей) эффективнее запускать 2–4 суб-агентов параллельно через `task`, а не последовательно. Каждый получает свой угол задачи. Сводка — формат «синтез роя» (точки согласия/расхождения/рекомендация). Handoff между агентами — через временный файл. Задокументировано в `docs/strategy/MASTER_INSTRUCTION.md` (раздел 5) и AGENTS.md (раздел «Оркестровка роя»).

## Симуляция бифуркаций: цифровой двойник для сценариев
(2026-07-27) Перед стратегическим решением (найм vs своё дело, переезд vs остаться, запуск vs заморозка проекта) — запускать симуляцию 2–3 сценариев через рой агентов. Каждый сценарий = отдельный агент. Матрица: прогноз на 1/6/12 мес, риски, следующий шаг. Формализовано в MASTER_INSTRUCTION.md (раздел 6).

## AOS Analyzer: одна точка входа
(F-015) Скрипт `scripts/aos_analyzer.py` — одна точка входа: --input (CSV/XLSX) → ключи: --score-cols (опционально, авто-детект), --group-by, --no-llm, --model. LLM-рекомендации — свободный формат (не 3+1). Промпт просит 4 секции: выводы, рекомендации, A/B-гипотезы, инсайты. Баг: если назвать функцию и переменную одинаково (`group_metrics`), Python перезатрёт функцию None.
