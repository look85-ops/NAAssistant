# Уроки работы с pptx через python-pptx

## Проблема: layout «обычный» из АП М1Д1 не существует в М1Д4
- `clone_from_presentation` падает, когда layout из source не найден в target.
- Fallback на «fbv основной слайд» работает, но элементы съезжают — оригинальные позиции не сохраняются.
- **Решение на будущее:** Импортировать не через `add_slide(layout)`, а полностью копировать XML слайда (`sldId` + `spTree` + `rels`), минуя `python-pptx` — напрямую через zipfile + lxml.

## Проблема: дубликаты rId при duplicate_slide
- `duplicate_slide` копирует spTree с перемаппингом rId через rid_map, но при множественных клонах возникают дубликаты rId в одном слайде.
- Фикс: пост-обработка XML — замена дублирующихся rId на новые, с созданием соответствующих записей в rels.

## Проблема: коррупция pptx
- Даже после фикса rId дубликатов PowerPoint всё равно просит восстановление.
- Вероятная причина: `python-pptx` через `add_slide()` + ручное копирование spTree создаёт неконсистентную внутреннюю структуру (slide ID, theme/master references).
- **Рекомендация:** для клонирования слайдов между презентациями — полностью копировать слайд как XML + rels + media через zipfile, не используя `prs.slides.add_slide()`.
- Альтернатива: использовать Open XML SDK (через subprocess) или COM-объект PowerPoint.

## Наблюдение
- M1Д1 — исправлен корректно (вероятно, меньше клонов между презентациями).
- M1Д2 и M1Д4 — съехали layout-ы (из-за fallback маппинга layout «обычный»).
