# Раскладка презентации по сценарию — принципы (М1Д4, 2026-07-31)

Проверенная методика переупорядочивания слайдов управляющей презентации
по новому сценарию. Результат: раскладка 202 слайдов М1Д4 «практически идеальна»
(по оценке Наташи) без повреждений, с сохранением скрытых слайдов.

## Принципы

### 1. Сценарий — единственный источник истины
- Порядок секций берём строго из сценария, даже если в файле он другой.
  В М1Д4 порядок Обеда и Приёмки/Временной эксплуатации в файле был иным —
  следовали сценарию.
- Маркеры `Слайд №N` / `Слайд N` — якоря для сопоставления. Собираем их
  все из сценария в один файл и строим соответствие «маркер → текущая позиция».
- Если в сценарии ссылка на слайды из другого модуля (блоки АП М1Д1:
  105–125, 178–189) — это «дырки», их НЕ заполняем и НЕ трогаем.
  Переупорядочивание идёт с дырками, а вставку слайдов модуля делает
  человек вручную в последнюю очередь.

### 2. Сначала карта, потом перенос
- Составляем целевую перестановку `target[конечная позиция] = текущая позиция`
  и валидируем её ДО переноса: ровно N позиций, 0 пропусков, 0 дублей.
- Карта хранится как массив в `build_target.ps1`, записывается в `target_order.txt`.
  Секции — комментариями, позиции — комментарием-названием слайда.
- Только после валидации карты запускаем COM-перенос.

### 3. Переупорядочивание — через PowerPoint COM (MoveTo), не XML-перестановкой
- Открывать с записью (ReadOnly=false), окно — false.
- Обрабатывать позиции **от конца к началу** (i = 202..1): так уже
  размещённые слайды не сбиваются последующими MoveTo.
- `SlideIndex` объекта обновляется автоматически — сравниваем текущую
  позицию с целевой и двигаем только несовпадающие (в М1Д4 из 202 — 97).
- Save в конце. После Save файл переименовывает slide-файлы: `slide{i}.xml`
  = новый i-й слайд, а `sldIdLst` идёт последовательно. Это нормально.

### 4. Валидация после переноса (все проверки зелёные перед «готово»)
- **Порядок:** фактический `sldIdLst` из `presentation.xml` vs `target_order.txt`.
- **Контент:** новый `slide{i}.xml` должен быть равен по текстам старому
  `slide{target[i]}.xml`. Сравнивать без учёта чистых чисел и «Модуль 1.»
  (авто-номера PowerPoint пересчитал — это ожидаемо и корректно).
- **Скрытые:** посчитать `show="0"` до и после (в М1Д4 26 → 26, позиции
  41–63, 146, 179, 198). COM-сохранение скрытость не сбрасывает — но проверяем.
- **Smoke-тест:** COM открывает файл, count = N, экспорт превью ключевых
  слайдов в PNG.

### 5. Технические грабли (проверено)
- **Кодировка PowerShell 5.1:** скрипты с кириллицей ломаются без BOM.
  После каждой записи/правки `.ps1` перекодировать в UTF-8 с BOM
  (`[System.Text.UTF8Encoding]::new($true)`).
- **Имена файлов:** в пути может быть длинное тире «—», а не дефис.
  Искать файл по glob (`Get-ChildItem ... | Where-Object { $_.Name -notmatch
  'backup|before_testslide' }`), а не хардкодить строку.
- **Консольная кодировка:** кириллица в выводе терминала показывается
  кракозябрами (cp866/cp1251) — писать результаты в UTF-8-файлы и читать
  их Read-инструментом, а не оценивать по консоли.
- **Превью:** PNG слайдов экспортируется, но визуально просмотреть их
  ассистент не может (модель без поддержки изображений) — слайды для
  визуальной проверки оставляем человеку.

### 6. Неоднозначности — подтверждать у Наташи до переноса
- «Слайд » без номера в сценарии → проверить, существующий ли это слайд
  (маркер-ссылка, а не новый).
- Разрывы блоков (178–187 перед слайдами X-Y, 188–189 после) — уточнить
  явно, не решать за неё.
- Дивайдеры-заглушки (пустой слайд «Модуль 1.») — вставлять как есть,
  не выдумывать контент.

### 7. Финальный файл Наташи = новая истина (урок из М1Д4)
- После раскладки Наташа корректирует вручную: объединяет слайды,
  меняет формат, переставляет единицы (в М1Д4: из 202 → 228 слайдов,
  вставлены АП-блоки, часть слайдов объединена/удалена).
- Ожидание: финальный файл будет расходиться с моей картой — это норма,
  а не ошибка. Сверяться с финалом (`_Fin.pptx`), а не с картой.
- Раскладка — это основа для ручной работы Наташи, а не конечный продукт.
  Не защищать свою карту, если автор по-другому объединила слайды.
- При сравнении финала с моей версией часть слайдов не сойдётся по тексту
  (объединённые/отредактированные) — это ожидаемо, искать соответствия
  по смыслу, а не по полному совпадению текста.

### 8. Неиспользуемые слайды — скрывать, не переносить (урок из М2Д1)
- Если в deck есть слайды, которых нет в сценарии (викторина М1, устаревший
  контент) — скрываем их (`SlideShowTransition.Hidden = -1` в COM, или
  `show="0"` в XML), НЕ переносим в конец.
- Причина: Наташе сложнее ориентироваться, если неиспользуемые слайды
  разбросаны по презентации. Скрытые не видны при показе, но есть в файле.
- В target_order всё равно включаем их (чтобы перестановка была полной),
  но на последние позиции — они окажутся скрытыми в хвосте и не помешают.
- Запомнить: всегда спрашивать Наташу, что делать с неиспользуемыми —
  скрыть или удалить. По умолчанию — скрыть.

### 9. Искать ВСЕ «Слайд» без номера, а не только в гапах (урок из М2Д2)
- Первый подход: искать discussion-блоки только между маркерами с gap ≥ 2.
  Это ошибка — слайды без номера (`Слайд` с пустым номером) могут быть
  где угодно, включая gap = 1 и начало сценария.
- Правильный подход: просканировать ВЕСЬ сценарий, собрать ВСЕ вхождения
  `Слайд` (и нумерованные, и без номера) в порядке появления. Строить
  целевую карту по этому полному списку. 35 слайдов в М2Д2 были пропущены
  из-за неверного подхода, пришлось переделывать.

### 10. Клон меняет структуру форм — всегда проверять (урок из М2Д2)
- `Duplicate()` в COM может изменить количество и структуру форм слайда.
  В М2Д2: оригинальный slide 10 имел 7 форм, клон — 5 форм (s4 и s7
  пропали или объединились с другими).
- **Перед массовым созданием слайдов** через клонирование: сделать тестовый
  клон, вывести все формы через COM (`Shapes.Count`, текст каждой), сравнить
  с оригиналом. Настроить индексы в скрипте под ФАКТИЧЕСКУЮ структуру клона.
- Индексы форм в оригинале ≠ индексы в клоне. Ориентироваться на клон.

### 11. PowerShell 5.1: ещё грабли
- `"$var:"` в двойных кавычках → `InvalidVariableReferenceWithDrive`.
  Использовать `"$($var):"` или конкатенацию.
- `@(1,2,5..7)` создаёт вложенный массив, не плоский.
  Использовать `@(1,2)+(5..7)` для объединения.

### 12. DOCX 270MB: Word COM виснет — иди через XML (урок из М3Д1, 2026-08-05)
- Если .docx весит >50MB (много вложенных PNG/SVG) — Word COM открывает его
  минутами или виснет намертво. Причина: документ «на лету» рендерит все
  изображения.
- **Решение:** открыть .docx как ZIP, достать `word/document.xml`, парсить
  lxml напрямую. Цвет шрифта — `w:rPr/w:color/@w:val`. Текст — `w:t`.
- Параграфы `Слайд №N` парсить жёстко: маркер = короткий параграф
  (≤60 символов), начинающийся с `Слайд` + номер. Всё остальное с «Слайд»
  в тексте — не маркер, а контент.

### 13. python-pptx не дружит с кириллицей в путях (урок из М3Д1, 2026-08-05)
- `pptx.Presentation()` падает с `PackageNotFoundError`, если в пути есть
  кириллица. **Решение:** копировать .pptx во временную папку с латиницей
  (например, `%TEMP%\opencode\pres.pptx`), работать там, результат копировать
  обратно.

### 14. Тегировать ТОЛЬКО изменённые слайды (урок из М3Д1, 2026-08-05)
- Не надо массово вешать `add_tag` на всё, что имеет контент. Только на
  слайды, которые действительно правились (Module fix, blue text, new slides,
  AP placeholders). Массовая тегировка создаёт ложное впечатление, что
  ВСЯ презентация переделана.
