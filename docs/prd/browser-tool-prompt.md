## Задача: настроить браузерный инструмент для ассистента NM.ASSISTANT

**Для кого:** Наташа (текущий пользователь)
**Цель:** дать ассистенту доступ к браузеру для задач, где `webfetch` не справляется (JS-сайты, интерактивные страницы).

**Что уже есть:**
- `webfetch` — работает для статических страниц и DDG Lite
- Прямой доступ к файловой системе (чтение/запись/скрипты)
- PowerPoint/Word через COM
- GitHub CLI (`gh`)

**Что нужно:**
- Возможность открыть URL в браузере, дождаться загрузки (включая JS), прочитать контент
- Желательно: заполнять формы, нажимать кнопки (мониторинг вакансий)
- В идеале: скриншоты страниц для визуальной проверки

**Конкретные сценарии использования:**
1. Research для дайджеста «Радар L&D» и «Сигнал» — GitHub trending, HN, новостные сайты с JS
2. Мониторинг вакансий на hh.ru, rabota.by, praca.by — открыть страницу поиска, прочитать результаты
3. Проверка портфолио/бустера — открыть в браузере, убедиться что работает
4. Работа с Notion (если понадобится)

**Возможные инструменты (список для ресёрча):**
- `@anthropic/computer-use` — MCP-сервер для браузера (Playwright под капотом)
- `Playwright MCP` — `@playwright/mcp` — официальный MCP-сервер от Microsoft
- `browserbase` — облачный headless-браузер с MCP
- `puppeteer-mcp` — Chrome DevTools Protocol через MCP
- `cloudflare/computer` — виртуальный компьютер для агента (включает браузерный backend)

**Ключевое требование:** локально (не облачный сервис, данные не уходят). В идеале — через Playwright + локальный Chrome.

**Контекст окружения:**
- Windows 10/11
- Python 3.14
- opencode CLI
- Chrome установлен

**Ожидаемый результат от нового диалога:**
1. Ресёрч 2-3 инструментов для браузерного доступа (локально, без облака)
2. Выбор лучшего варианта
3. Установка и настройка
4. Smoke-test: открыть страницу, прочитать текст
5. Интеграция в opencode (MCP или команда)
6. Запись в `knowledge/` и `logs/decisions.md`
