# PRD: Портал «L&D без суеты»

**Дата:** 2026-09-15
**Автор:** Наташа + ассистент
**Статус:** Draft

---

## 1. Контекст и проблема

У Наташи есть три продукта, которые живут раздельно:
- **Бустер методиста** — 6 инструментов, GitHub Pages, готов, фокус-группа довольна
- **Курс «Методист в эпоху AI»** — 3 модуля готовы, М4 в плане, пилот на фокус-группе
- **Радар L&D** — дайджест, 1 выпуск собран, формат утверждён

Сейчас это три отдельные точки. У каждой — своя аудитория (или её отсутствие), своя навигация, нет перекрёстных переходов. Бустер не ведёт на курс, курс не ссылается на Радар.

**Единый портал** решает:
- Собирает разрозненные продукты в экосистему под одним брендом
- Даёт посетителю маршрут: «заинтересовался блогом → попробовал Бустер → записался на курс»
- Усиливает позиционирование Наташи как эксперта («это не хобби-поделки, это система»)

**Связь с целями:**
- Фаза 1 (Q4 2026 — Q2 2027): найм в Минске + учёба. Портал — витрина компетенций для нанимающего менеджера.
- Фаза 2 (Q3 2027+): EdTech-продукт. Портал — готовая площадка для запуска платных продуктов.

---

## 2. Цель и гипотеза

**Результат:** единая точка входа `ldbezsuety.ru` (или GitHub Pages), с которой посетитель за 10 секунд понимает кто это, что предлагает и куда идти дальше.

**Гипотеза ценности:** методисту не нужна гонка. Нужен порядок, глубина и нестандартные решения — а AI берёт рутину на себя, освобождая место для вдумчивой работы.

**Ценности бренда:** порядок, глубина, нестандартные решения, спокойный взгляд.
**Анти-ценности:** «быстрее», «эффективнее», гонка, «ускорение».

## 3. Скоуп

### Входит
- **Главная страница:** ценностное предложение, навигация по продуктам
- **Бустер методиста:** 6 инструментов (уже готов, требуется лёгкий ребрендинг — единый заголовок, ссылка на портал)
- **Курс:** страница с программой 4 модулей, целевой аудиторией, форматом, CTA «Предзапись»
- **Блог:** страница-оглавление выпусков Радара L&D + страницы отдельных выпусков
- **Сквозная навигация:** шапка/футер на всех страницах
- **Единый дизайн-голос:** «Тихая уверенность» (бумага/чернила/сургучный красный)
- **Адаптивность:** mobile-first, десктоп — основной сценарий
- **Дежурное обновление:** дата последнего апдейта в футере, актуальные ссылки

### Не входит
- Приём платежей (пока — внешние ссылки на Boosty/Patreon)
- Личный кабинет, авторизация
- Аналитика
- Тёмная тема
- Мультиязычность (только русский)
- Миграция Радара в рассылку (это отдельная задача, после запуска портала)

### 4.2 Бустер методиста

**Подход:** не переписывать с нуля. Существующий Бустер на GitHub Pages получает:
- Единую шапку с навигацией портала (← Главная | Курс | Блог)
- Заголовок обновлён: «Бустер методиста» → подзаголовок в голосе бренда
- Футер в стиле портала
- Кнопку «Глубокие протоколы» (платный блок, внешняя ссылка на Boosty)

Дизайн инструментов (Inter, градиенты, 5 цветов) сохраняется — он работает и узнаваем.

## 5. Дизайн-голос

**«Тихая уверенность»** — editorial-минимализм + аналитическая сетка.

### Палитра
```
--bg:           #F4F0E8   бумага
--text:         #1E1D1B   чернила
--accent:       #A6332E   сургучный красный (основной CTA)
--secondary:    #2B3A55   глубокий синий
--muted:        #8A8579   приглушённый (мета-информация)
--border:       #D4CFC4   границы
--bg-elev:      #FFFFFF   белая карточка на бумаге
```

### Типографика
```
--font-heading: Literata (serif, заголовки)
--font-body:    Golos Text (основной текст)
--font-mono:    JetBrains Mono (метки, номера, даты)
```

### Принципы
- Минимум цвета: один акцент (сургучный) на страницу
- Без эмодзи, градиентов, теней, глейма
- Без канцелярита и AI-клише
- Воздух и паузы между секциями
- Номера страниц / разделов — моноширинным шрифтом

### Заимствование из существующего
- Бустер сохраняет свой дизайн (Inter, градиенты, 5 цветов) — он узнаваем и работает
- Портал даёт «зонтик» с единой навигацией и общим голосом
- Курс и Блог — с нуля в голосе «Тихая уверенность»

## 6. Метрики успеха

**Основные (после запуска):**
- Портал открывается с телефона и десктопа без горизонтального скролла
- Все ссылки в навигации рабочие
- С главной страницы посетитель находит Бустер и Курс за ≤ 2 клика
- Lighthouse: Performance ≥ 90, Accessibility ≥ 95

**Вспомогательные (после 3 месяцев):**
- Количество переходов из Блога → Бустер / Курс
- Предзаписи на курс (цель: 5+ до запуска)

## 7. Риски и допущения

### Pre-Mortem

**Три причины провала:**
1. Портал сделан, но не обновляется — через месяц выглядит заброшенным, подрывает доверие
2. Бустер и Курс живут в разных дизайн-голосах — портал выглядит лоскутным, а не единым
3. Сделали красиво, но забыли про мобильных — 60% трафика потеряно

**Три причины сожаления (если не делать):**
1. Три продукта продолжают жить отдельно — каждый требует усилий на продвижение, нет синергии
2. Нанимающий менеджер видит разрозненные ссылки, а не систему — упущенный аргумент на интервью
3. Радар остаётся без постоянного места — формат умирает без регулярности

### Допущения
- Курс будет готов (М4 дописан) к моменту запуска страницы курса
- Бустер не требует переписывания — лёгкий ребрендинг достаточен
- GitHub Pages справляется с хостингом (статический HTML)

## 8. Требование актуализации (CRITICAL)

**Портал должен выглядеть живым всегда.**

- **Дата последнего обновления** — в футере, видна на всех страницах. Автообновляется при деплое.
- **Блог:** минимум 1 выпуск в месяц. Если выпуска нет > 30 дней — на странице блога появляется пометка «Следующий выпуск — скоро».
- **Курс:** статус модулей актуален (М4: «в разработке» → «готово» после дописывания).
- **Бустер:** если добавлен новый инструмент — отражено на главной.
- **Проверка раз в месяц:** все внешние ссылки (Boosty, Telegram, LinkedIn, портфолио) рабочие.
- **Ответственный:** ассистент при `/verify` ритуале проверяет дату последнего обновления и рабочие ссылки. Если > 30 дней без апдейта — флагнуть Наташе.
