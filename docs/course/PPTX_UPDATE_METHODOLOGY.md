# Актуализация управляющих презентаций «Профессионал+. Путь»

Инструкция для агента (ассистента) по актуализации PowerPoint-презентаций
по обновлённым сценариям. Написана после первого прохода по М1Д1 (стр. 1–48
сценария) — учитывает ошибки, которые нельзя повторять.

Область применения: все презентации серии «П+Путь» (М1–М4 × Д1–Д5), и
серии «П+Энергия» — там та же логика.

## 0. Ключевые факты о файле

- Размер слайда: **20 × 12.5 дюйма** (широкий, не 16:9 стандартный).
  При создании текстбоксов исходить именно из этих размеров, иначе
  контент собьётся в угол.
- Пути:
  - Сценарий: `Сценарий_М1Д1_26.docx` (шрифт голубого цвета =
    новый контент, требующий отражения в слайдах).
  - Презентация с правками автора: `Управляющая_презентация_М1Д1_26.pptx`.
  - Исходная: `Управляющая_презентация_М1_Д1.pptx` — только для сверки.
- Служебные метки автора на слайдах:
  - **«Новый»** — слайд создан заново.
  - **«Изменено»** — переработан существующий слайд.
  Метки ставить в правый верхний угол, красным, италик, ~24pt.

## 0.1. Что попадает на слайды, а что нет (жёсткое правило)

**НЕ выносим на слайд:**
- всё, что идёт после метки `Примечание:` — это методические
  ремарки для ведущего (тайминги, инструкции по фасилитации).

**Выносим на слайд:**
- всё, что помечено `Слайд` или `Слайд №N` (номер не важен —
  важно само указание);
- реплики после `Преподаватель:` — выносим тоже, автор потом
  вручную вычистит лишнее (агенту трудно надёжно отличить,
  что «на экран», а что «в речь»);
- вопросы участникам, если они помечены как «Слайд» или являются
  единственным содержанием шага (QUESTION_MOD1 / DISCUSS).

## 0.2. Сценарий — единственный источник истины

Правило номер один: **актуальная информация — только в сценарии.**
Любое расхождение между сценарием и презентацией трактуется в пользу
сценария. Презентация подстраивается под сценарий, никогда наоборот.

Что это означает на практике:

- Если содержимое в презентации противоречит сценарию — переписать
  под сценарий.
- Если в презентации есть слайд, которого нет в сценарии, — это
  устаревший контент. По умолчанию **скрываем** (не удаляем — вдруг
  автор захочет вернуть), помечаем для ревью.
- Если в сценарии есть контент, которого нет в презентации, —
  добавляем новый слайд (клонированием подходящего образца).

## 0.3. Порядок слайдов = порядок по сценарию

Номера слайдов в сценарии и в презентации **могут не совпадать**
(автор поправит номера в сценарии потом). При актуализации агент
ориентируется на **последовательность появления информации в сценарии**,
а не на нумерацию.

Если сценарий говорит: сначала вопрос → потом теория → потом
самостоятельная работа — именно в таком порядке слайды и располагаются.
Если это ломает исходный порядок в презентации — приоритет за
сценарной логикой.

## 1. Каталог типов слайдов (шаблонов)

Классификация ниже выведена из фактических layout-имён и содержания слайдов.
При добавлении нового слайда — **всегда клонируем ближайший подходящий
образец из существующей презентации**, а не создаём с нуля.

| Тип | Layout name | Пример-эталон | Когда использовать |
|---|---|---|---|
| COVER | `Пустой слайд` | 1 | Титульный слайд программы |
| SECTION_INTRO | `Фирменная рамка №2` | 4 | «Архитектура программы» — вступительный |
| SECTION_HEADER | `fbv тема` | 11, 45, 67 | Заголовок раздела/подраздела в теле дня |
| CONTENT | `Только заголовок` | 5, 6, 13, 14, 15… | Обычный слайд с текстом/списком/таблицей |
| QUESTION_MOD1 | `Фирменная рамка №1 (макс)` | 12, 16, 17, 47, 50 | «Модуль 1. + вопрос» — фронтальные вопросы |
| DISCUSS | `Фирменная рамка №1 (макс)` | 28, 68, 70 | «Модуль 1. + Обсудим/Поразмышляем + вопрос» |
| SELFWORK | `Фирменная рамка №1 (макс)` | 29, 43, 63 | «Самостоятельная работа + тетрадь + время» |
| BREAK | `Фирменная рамка №1 (макс)` | 9, 44 | «ПЕРЕРЫВ 15 МИНУТ» |
| QUESTION (без «Модуль 1.») | `Фирменная рамка №1 (макс)` | 2, 8 | Первичные вопросы («Зачем мы здесь?», «Знакомство») |

**Правило подбора шаблона.** Читая сценарий и решая «а какой это слайд»,
смотрим на маркеры в тексте:
- «Вопрос участникам:» → QUESTION_MOD1
- «Обсудим/Поразмышляем» → DISCUSS
- «Объединитесь в подгруппы / Рабочая тетрадь: страница X» → SELFWORK
- «Кофе-пауза», «Перерыв 15 минут» → BREAK
- Заголовок раздела дня («Организация работы хозяйства пути и сооружений»
  без вопроса) → SECTION_HEADER
- Всё остальное с содержанием/таблицами/схемами → CONTENT

## 2. Алгоритм актуализации (для одного дня программы)

### Шаг 1. Извлечение сценария

1. Прогнать `word_pages.py` — открывает docx через Word COM,
   собирает `scenario_pages.json` (список параграфов с номером страницы
   и флагом `has_blue`).
2. Прогнать `scenario_report.py` — фильтрует по диапазону страниц,
   строит `scenario_pXX_YY.txt` с метками `[NEW]` для голубого текста
   и `scenario_slide_refs.json` (места, где сценарий ссылается на слайды
   формата «Слайд №N»).

### Шаг 2. Каталогизация текущей презентации

1. `catalog_types.py` — читает pptx, выдаёт каталог слайдов с типом
   для каждого. Сохраняет `catalog.json`.
2. Смотрим, что уже сделано автором (метки «Новый»/«Изменено» на слайдах).
3. Смотрим, что просит сценарий: где новый контент, где корректировка.

### Шаг 3. Планирование правок (обязательно проговорить с автором)

Готовим план в формате таблицы:

| # | Действие | Куда | Тип | Источник контента |
|---|---|---|---|---|
| 1 | ДОБАВИТЬ | перед слайдом N | QUESTION_MOD1 | стр. XX сценария, «[NEW] Вопрос…» |
| 2 | ИЗМЕНИТЬ | слайд M | — | стр. YY, [NEW] строки |
| 3 | СКРЫТЬ | слайды K..L | — | сценарий не ссылается |
| 4 | ДУБЛИРОВАТЬ | слайд S → перед T | CONTENT | нужен дополнительный слайд той же темы |

**Обязательно:** согласовать план с автором до внесения правок.

### Шаг 4. Внесение правок

**Основные операции (реализованы в `pptx_edit.py`, см. §3):**

- `duplicate_slide(prs, src_idx)` — клонирует существующий слайд
  побайтово (со всеми фигурами, форматированием, отношениями). Возвращает
  новый слайд, добавленный в конец.
- `move_slide(prs, slide, new_index_1based)` — переставляет слайд
  в нужную позицию в порядке показа.
- `hide_slide(slide)` — прячет слайд от показа (атрибут `show="0"`).
- `set_slide_text(slide, mapping)` — заменяет текст в конкретных
  фигурах по частичному совпадению «старый → новый», сохраняя
  форматирование run-ов.
- `add_tag(slide, "Новый" | "Изменено")` — добавляет служебную метку.
- `replace_slide_content_in_place(slide, {…})` — редактирует текст
  in-place, не пересоздавая фигуры. Именно так работаем со «слайд 30».

**Правило (главное):** **никогда не создавать слайд «с нуля»** — только
дублирование образца + подмена текста + добавление метки. Это сохраняет
фирменное оформление (рамка, шрифты, фон) и не ломает нумерацию/стиль.

**Порядок вставки нескольких слайдов подряд.** Если добавляем 3 слайда
перед позицией N — сначала все три дублируются (уходят в конец),
затем перемещаются в обратном порядке (сначала последний, потом
предпоследний, потом первый), чтобы позиции не сдвигались.
Пример:
```
new3 = duplicate(sample_C); move(new3, N)
new2 = duplicate(sample_B); move(new2, N)
new1 = duplicate(sample_A); move(new1, N)
# итог: N=new1, N+1=new2, N+2=new3
```

### Шаг 5. Верификация

1. Пересобрать `catalog.json` — проверить, что типы новых слайдов
   соответствуют плану.
2. Открыть файл через PowerPoint COM (`verify_pptx.py`) — убедиться,
   что файл открывается без ошибок.
3. Дать автору посмотреть глазами — обязательный шаг перед следующим днём.

### Шаг 6. Фиксация решения

Записать в `logs/decisions.md`:
`F-XXX: М?Д? актуализирован — добавлено/скрыто/изменено N слайдов
(ссылка на новый контент из сценария, стр. X–Y).`

## 4. Ошибки, которые нельзя повторять

1. **Создавать текстбоксы под 13.33×7.5**, когда слайд 20×12.5 —
   контент собьётся в левый верхний угол. Всегда читать `slide_width`
   / `slide_height` из презентации.
2. **Строить слайд с нуля через add_textbox** вместо клонирования —
   теряется фирменная рамка, шрифты, фон. Только `duplicate_slide` +
   `set_slide_text`.
3. **Переопределять layout существующего слайда** через python-pptx —
   он этого не умеет. Если нужно изменить тип слайда — лучше:
   продублировать нужный образец → перенести на позицию → скрыть
   старый (или удалить, если автор согласен).
4. **Не согласовывать план с автором** — правки становятся некорректными,
   приходится восстанавливать из бэкапа.
5. **Забывать про бэкап**. Перед каждой сессией правок — копия файла
   с суффиксом `_backup_<timestamp>.pptx` рядом.
6. **Игнорировать таблицы**. В сценарии таблицы («Направления развития…»)
   должны становиться слайдами с настоящей таблицей PowerPoint
   (CT_Table), а не набором текстбоксов.

## 5. Что делать с большими таблицами

Если в сценарии таблица на 5+ строк и 2+ столбца — вставляем
на слайд именно `slide.shapes.add_table(rows, cols, x, y, w, h)`,
не набор боксов. Стилевое оформление таблицы: заголовок жирный,
строки чередующимся фоном (по-умолчанию у python-pptx нормально).
Если таблица не влезает — разбиваем на 2 слайда с суффиксами
«(1/2)», «(2/2)», как договорились с автором.
