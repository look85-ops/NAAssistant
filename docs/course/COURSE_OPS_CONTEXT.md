## П+Путь («Профессионал+. Путь»)

**ЦА:** начальники дистанций пути (ПЧ, ПЧЗ, ПЧГ, ПЧУ) + потенциально ПЧУ-резерв.

**Роли участников:**
- **Слушатели (18 ролей):** ПЧ (начальник дистанции пути), ПЧЗ (заместитель), ПЧГ (главный инженер), ПЧУ (начальник участка), П, ПЗ, ПД, ПДБ, ПДБк, ИТ, М, Д, ДС, ТЧ, ШЧГ, В, НГ, ЭЧК
- **Преподаватели (3 роли):** A (эксперт), B (модератор), C (тек. содержание + активные методы)

**Структура модулей:** М1–М4, каждый модуль — несколько дней (Д1–Д4).

**Артефакты каждого дня:**
- Управляющая презентация (.pptx)
- Сценарий (.docx) с маркерами слайдов
- Слайды вшиваются в сценарий через XML-манипуляции

**Ключевые файлы проектов:**
- `projects/stack-ld-ai/` — учебные материалы
- `knowledge/pptx/` — технические уроки по pptx (рабочее направление — `scenario-slide-autonumbering.md`)

**Правила разработки:**
- Номера «Слайд №N» в сценарии ставить по **текстовому соответствию** (TF-IDF +
  монотонное выравнивание), а не по порядковому номеру или SlideID
- Вставка слайдов только через `lxml`+`zipfile`, не `python-docx.save`
- Работать с копиями файлов, не редактировать оригинал напрямую
- При появлении `_fin`-файлов (финальная версия от Наташи) — инвалидировать старые карты и PNG
- Не угадывать смысл голого маркера «Слайд», пропусков, пустых слайдов — при неоднозначности спросить

**Приоритет П+Путь над другими курсами.** Дедлайн М4: 15 сентября 2026.

## П+Энергия

**Актуальный источник:** концепция v2 от 29.09.2026, направлена заказчику на согласование после второй встречи 24.09.2026. Сводка: `knowledge/course/energy-concept-v2-2026-09-29.md`.

**ЦА:** начальники дистанций электроснабжения, главные инженеры и заместители.

**Статус:** второй вариант концепции и РП М1–М4 сформированы и направлены на согласование. Модель профессиональных компетенций находится в пилоте; финальные номера и индикаторы нужно обновить после утверждения.

**Объём и формат:** 190 академических часов: 160 контактных + 30 электронного обучения; 40% теории и минимум 60% практики.

**Сквозной результат:** учебный проект «Программа повышения надёжности предприятия» на один год. Четыре результата собираются последовательно: паспорт подразделения → охрана труда → доходы → надёжность. После М4 — первый 90-дневный цикл.

**Методические правила v2:** работать со своими данными, включать стажировку с наблюдением и АСУ, давать межмодульные задания, начинать следующий модуль с разбора предыдущего результата, не обещать прямой эффект обучения на системные показатели без дизайна измерения.

## Работа с pptx

> ⚠️ **Устарело (2026-10).** Перечисленные ниже скрипты вставки/правки слайдов
> (`insert_slides_batch.py`, `pptx_pipeline.py`, `pptx_com.py`) работают плохо и
> выведены из оборота. Рабочий принцип направления «презентация → сценарий»
> (нумерация «Слайд №N» + вставка скринов): рендер .pptx → PNG через COM
> PowerPoint (2500×1406), сопоставление плашек со слайдами по тексту
> (TF-IDF + монотонное выравнивание), вставка через `lxml`+`zipfile`
> (НЕ `python-docx.save`). Подробно — `knowledge/pptx/scenario-slide-autonumbering.md`.

**Ключевые скрипты (историческая справка, большинство устарело):**
- `scripts/insert_slides_batch.py` — пакетная вставка (⚠️ устарел)
- `scripts/insert_slides_explicit.py` — явная вставка по SlideID (⚠️ устарел)
- `scripts/insert_slides_before_text.py` — вставка перед текстовым якорем (⚠️ устарел)
- `scripts/pptx_pipeline.py` — полный пайплайн (⚠️ COM-правки устарели)
- `scripts/pptx_com.py` — COM-автоматизация (⚠️ устарел)
- `scripts/report_docx_slide_locations.py` — отчёт о местоположении слайдов в docx

**Технические правила:**
- Клонирование слайдов через python-pptx: использовать layout индекс 0 (fallback при отсутствии именованного layout)
- При клонировании проверять rId дубликаты в связях (relationships)
- COM-автоматизация: избегать кириллицы в TextBox (баг COM)
- Всегда проверять документ после правок: `document.xml`, `footer*.xml.rels`, `header*.xml.rels`

**Стоп-критерии (из ретро М1Д2):**
1. В начале — manifest с SHA-256 обоих входов
2. Новый `_fin`-файл → новая карта с нуля
3. Mapping.json до вставки
4. Не угадывать — при неоднозначности стоп
5. Финальный gate: слайды = маркеры = картинки, нет orphan, единый размер
6. Результат во временный файл, замена только после всех проверок
7. Визуальная сверка человеком: начало, границы секций, последние 10 слайдов
