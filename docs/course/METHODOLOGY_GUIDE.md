# Методическая концепция курса «L&D × AI: учебный стек»

## 1. Команда

| Роль | Кто | Что делает |
|---|---|---|---|
| Методист + продакт | Я | Пишу материалы, проверяю артефакты, отвечаю на вопросы, адаптирую программу |
| Студенты | Группа L&D-специалистов | Проходят модули, делают практику, дают обратную связь |
| Frontend-разработчик | frontend_developer (по запросу) | GitHub Pages — хаб курса (навигация, трекер, артефакты) |

## 2. Формат доставки

**Основной носитель:** DOCX + MD (каждый урок — два файла в одной папке). DOCX для чтения, MD для версионности и коллаборации.
**Хаб курса:** GitHub Pages (навигация по модулям, трекер прогресса, ссылки на артефакты) — по желанию, когда накопится контент.
**Канал связи:** чат (вопросы, рефлексия, обратная связь).

## 2a. Структура папок курса

```
stack-ld-ai/
├── module-01-technical-minimum/
│   ├── lesson-01-terminal/
│   │   ├── lesson-01-terminal.md
│   │   └── lesson-01-terminal.docx
│   ├── lesson-02-git/
│   └── lesson-03-api/
├── module-02-ai-from-prompt-to-product/
├── module-03-ai-strategy-and-roi/

```

Все уроки хранятся в `stack-ld-ai/`, а не в `docs/course/`. `docs/course/` — только для курсов заказчиков (РЖД).

## 3. Структура одного урока (недели)

Каждый урок — DOCX-файл с разделами:

1. **Цель недели** — 1 абзац, что будет уметь после
2. **Теория** — концепции на пальцах, 1–2 страницы
3. **Шпаргалка** — команды/термины/шаги
4. **Практика** — упражнения от простого к сложному (80 % времени)
5. **Рефлексия** — 4 вопроса (время, трудности, польза, оценка)
6. **Чек-лист готовности** — 3–5 пунктов для самопроверки
7. **Артефакт** — что должно появиться в репозитории
8. **Что дальше** — анонс следующей недели + допматериалы

## 4. Проверка знаний

Уровни освоения каждого артефакта:

| Уровень | Критерий | Как проверяю |
|---|---|---|
| 🟢 Сделано | Файл создан, структура соблюдена | Визуально в репозитории |
| 🟡 Понято | Может объяснить своими словами | 1 устный вопрос в чате |
| 🔴 Применено | Использует в реальной работе | Через месяц после модуля |

Критерии готовности урока — чек-лист. Пример:
```
[ ] Создана папка terminal-demo
[ ] Создан файл cheatsheet.md с 5+ командами
[ ] Выполнены упражнения 1–7
[ ] Написана рефлексия
```

## 5. Обратная связь

**После каждого урока** — 4 вопроса в чат:
1. Сколько времени заняло?
2. Что было самым непонятным?
3. Что было самым полезным?
4. Оценка материала от 1 до 5

**После модуля** — structured feedback в файл `docs/course/feedback/`:
- Что получилось лучше всего?
- Что можно улучшить в подаче?
- Какая тема была лишней?
- Какой темы не хватило?
- Готова ли рекомендовать модуль коллеге?

## 6. Оценка успеха продукта

Критерии, что курс сработал:

| Критерий | Как измеряю |
|---|---|
| Прохождение | Прошла все 4 модуля до конца |
| Артефакты | Все артефакты в репозитории, структура соблюдена |
| Навык | Делает commit сама, читает API-документацию, объясняет RAG vs fine-tuning |
| Рекомендация | Сказала бы «это стоит пройти» |
| Применение | Использует что-то из курса в работе (Git, AI-агент, стратегия) |
| Удовлетворённость | Средняя оценка материалов ≥ 4/5 |

## 7. Что мне нужно от студента

- 2–3 ч/нед на практику
- Рефлексия после каждого урока (4 вопроса в чат)
- Вопросы в процессе (не ждать конца недели)
- Честная обратная связь

## 8. Правила для материалов

- **Глобальная цель курса.** L&D-специалист, который управляет AI-инструментами, а не просто их использует. Каждый урок явно отвечает на вопрос «зачем это L&D-специалисту в работе с AI».
- **Связка с AI.** В начале каждого урока — абзац, как тема связана с AI-задачами (через терминал запускают AI-агентов, через Git версионируют промпты, через API делают запросы к моделям).
- **Обезличивание.** Все примеры даются в общем виде: `C:\Users\ИмяПользователя\`, без имён, без ссылок на конкретные проекты студентов. Курс идёт для группы.
- **Формат.** Каждый урок = `.md` (версионность) + `.docx` (чтение).
- **Повествование.** В материалах — «вы», в чате — индивидуально.
- **Не сохранять в материалах.** Внутренние комментарии, служебные пометки, «для методиста» — в чат или отдельный файл, не в урок.

## 9. Типичные ошибки и как их избегаю

| Ошибка | Как предотвращаю |
|---|---|
| Слишком много текста | Теория — только самое нужное, 80 % — практика |
| Нет связи с реальностью | Каждое упражнение привязано к её проектам |
| Зависла и молчит | После 3 дней без активности — напоминаю |
| Непонятен термин | Определение одной строкой + бытовая метафора |
| Слишком легко/сложно | Адаптирую темп после первого модуля |
