## Что делать

Запустить Фазу A конвейера `pptx_pipeline` для модулей М4Д2 и М4Д4
(актуализация «сценарий → презентация»), затем раскладка.

## Точный скоп Фазы 1 (Фаза A)

Для каждого модуля выполнить подкоманды конвейера:

1. `parse` сценария → scenario.json
2. `catalog` презентации → catalog.json
3. `diff` → diff.md (что добавить / исправить / скрыть)
4. `update` с реальными operations.json (clone/edit/hide) — правки по diff
5. `layout` по порядку сценария (target_order.txt)
6. `validate` — проверка (кол-во слайдов, скрытые, файл открывается)

Фаза B (`export` + `insert`, вставка скриншотов в сценарий) — ОТДЕЛЬНО, после
возврата презентации от дизайнера. В Фазу 1 НЕ входит.

## Ключевые правила (не нарушать)

- Сценарий — единственный источник истины. Ориентируемся на контент, не на
  номера «Слайд №N».
- Новые слайды — только COM-клонированием доноров + замена текста + красная
  метка «Новый». «С нуля» — нельзя.
- `Примечание:` на слайды не выносим; реплики `Преподаватель:` и вопросы — выносим.
- Устаревшее — скрываем, не удаляем.
- Исходники не перезаписывать: работа через temp-копии с латинскими именами,
  `--backup` при каждой сессии правок.
- Крупные docx (>50MB) — XML-парсер (`parse_scenario_xml.py`), правки больших
  pptx — только через COM (`pptx_com.py`).
- Кириллица в stdout ломается — читать результаты из UTF-8-файлов, не из консоли.

  (обёртка с `$env:PYTHONIOENCODING="utf-8"`).
