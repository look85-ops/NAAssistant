# Принципы хороших агентов и команд

Адаптировано из `mattpocock/skills/writing-great-skills`.

## 1. Одна ответственность

Одна команда — одно действие. Если команда пытается делать два дела — раздели.

- **Плохо:** `/task-manager` (создаёт, редактирует, удаляет, архивирует)
- **Хорошо:** `/idea` (только превращает идею в фичу), `/start-task` (только начинает разработку)

## 2. Предсказуемый формат

Пользователь должен знать, что будет на выходе, ещё до вызова.

- У каждой команды — чёткая структура ответа
- Одинаковые секции — одинаковый порядок
- Формат фич, PRD, планов — шаблоны

## 3. Минимальность

Каждая строка в команде или агенте должна работать. Если строку можно удалить без потери смысла — удали.

- Нет «воды»: общих фраз, канцелярита, самоочевидных указаний
- Нет дублирования с AGENTS.md или другими файлами — используй ссылки
- Нет инструкций «на будущее» — только то, что нужно прямо сейчас

## 4. Композируемость

Команды должны вызывать друг друга, а не дублировать логику.

- `/grill` → после подтверждения вызывает `/start-task`
- `/idea` → вызывает `product-analyst`, потом пишет в BACKLOG.md
- Не копируй процесс из одной команды в другую — ссылайся

## 5. Явные границы

У каждой команды должно быть понятно:
- Когда вызывать (триггеры)
- Когда НЕ вызывать
- Что делать, если что-то пошло не так

## 6. Единый голос

Все команды и агенты пишутся в одном стиле:
- MD-заголовки второго уровня (`##`) для секций
- Списки для шагов и критериев
- Короткие абзацы
- Без эмодзи, без пафоса

## 7. Ошибка — это сценарий

Любая команда должна описывать, что делать при ошибке:
- Файл не найден → создать / спросить
- Не хватает данных → запросить у пользователя
- Команда не подходит для контекста → объяснить почему и предложить альтернативу
