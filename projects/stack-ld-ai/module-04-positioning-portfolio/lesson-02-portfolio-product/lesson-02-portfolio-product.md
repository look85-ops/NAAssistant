### 2.1. Почему портфолио методиста — это не «10 программ, которые я разработала»

Традиционное портфолио методиста — список курсов и программ: «Разработала 15 дистанционных курсов», «Внедрила СДО в 3 филиалах». Для нанимателя это шум. Он не понимает, что стоит за каждым пунктом, и не видит вашей роли в результате.

**Метафора:** портфолио — не музейная экспозиция («вот всё, что я когда-либо делала»), а витрина магазина. В витрину ставят 3–4 товара, которые продают. Остальное — на складе, достаёте по запросу.

**Правило сильного портфолио:** 3 кейса с результатом лучше, чем 10 проектов без контекста.

Почему именно 3:
- 1 — человек запоминает с трудом («что-то про обучение»)
- 2 — создаёт контраст («она и про онбординг, и про аналитику»)
- 3 — формирует паттерн («она системно решает L&D-задачи с помощью AI»)
- 4 и больше — размывает фокус («много всего, а в чём специализация?»)

**Что должно быть в каждом кейсе портфолио (публичная версия):**

| Элемент | Содержание | Пример |
|---|---|---|
| Заголовок | Глагол + объект + AI | «Сократила онбординг с 2 месяцев до 3 недель с помощью AI-агента» |
| Контекст | 1 предложение — где, для кого, масштаб | «Производственная компания, 500+ новичков в год» |
| Задача | 1 предложение — боль бизнеса | «Новички тратили 40 % времени на поиск информации, отток на испытательном — 22 %» |
| Решение | 2–3 предложения — что сделали, инструменты | «Собрала RAG-агента на внутренних регламентах. Агент отвечает на вопросы в чате со ссылками на документы. Human-in-the-loop: выборочная проверка диалогов раз в неделю» |
| Результат | 1 предложение + цифра | «Time-to-competence: с 8 до 5 недель. Нагрузка на наставников: −35 %. Отток за 6 месяцев пилота: с 22 % до 10 %» |
| Ваша роль | 1 предложение — конкретно вы | «Спроектировала архитектуру агента, написала промпты, провела пилот на 30 новичках» |

**Антипаттерны портфолио (чего избегать):**
- «Участвовала в проекте по...» — не видно роли
- «Внедрила AI в обучение» — не видно результата
- Список из 10+ проектов одной строкой — шум
- Скриншоты без контекста — непонятно, на что смотреть
- «Разработала программу для...» без цифр — не видно ценности

Вы прошли три модуля этого курса, и у вас уже есть материалы для портфолио. Даже если вы не делали «боевых» проектов на работе — учебные артефакты показывают ваш способ мышления.

**Инвентаризация: что у вас есть по итогам модулей 1–3:**

| Модуль | Что создали | Как это превратить в кейс |
|---|---|---|
| Модуль 1 «Технический минимум» | Шпаргалка по терминалу, Git-демо (log коммитов), пример API-запроса | Не кейс, а доказательство: «я умею работать с инструментами разработчика». Добавьте ссылку в LinkedIn или GitHub. |
| Модуль 2 «AI: от промпта до продукта» | Проект AI-агента (промпты, схема, скриншоты) | Кейс: «Спроектировала AI-агента для [задачи]». Покажите архитектуру, промпт, результат тестирования. |
| Модуль 3 «AI-стратегия и ROI» | AI Readiness Check, матрица use case'ов, дорожная карта ROI | Два варианта: (1) кейс «Провела AI-аудит отдела и защитила дорожную карту на год» — если делали для реального отдела; (2) раздел «Методология» в портфолио — «вот как я подхожу к AI-внедрению», если делали учебно. |
| Модуль 4 (Урок 1) | Narrative, elevator pitch, 3 кейса | Основа портфолио. Кейсы из Урока 1 — это и есть контент для сайта. |

**Принцип:** не создавайте новое — упакуйте существующее. Лучше 3 кейса, которые уже написаны и отполированы, чем 10 наспех придуманных.

**Если у вас есть реальные проекты с работы — используйте их.** Учебные артефакты — это страховка, а боевые проекты — это валюта. Просто обезличьте названия компаний и замените внутренние термины на общепонятные.

### 2.3. GitHub Pages за час: из README → сайт-визитка

Вам не нужен конструктор сайтов, дизайнер и бюджет. GitHub Pages — бесплатный хостинг, который работает из вашего репозитория. Вы пишете Markdown — он становится сайтом.

**Метафора:** GitHub Pages — это как повесить ваше резюме на дверь офиса. Вы не строите офис — вы просто делаете так, чтобы проходящие мимо могли прочитать.

**Что вам понадобится:**
1. GitHub-аккаунт (у вас уже есть, если вы прошли Модуль 1)
2. Репозиторий с материалами курса
3. Один файл `index.md` или `README.md` как главная страница
4. 15–20 минут на настройку

**План действий (пошагово):**

**Шаг 1. Создайте файл `index.md` в корне репозитория.**

Это будет ваша главная страница. Минимальная структура:

```markdown
# [Ваше имя] — L&D × AI

[Одна фраза позиционирования — из Урока 1]

## Что я делаю

[2–3 предложения из elevator pitch на 2 минуты]

## Кейсы

### [Название кейса 1]
**Задача:** ...
**Решение:** ...
**Результат:** ...

### [Название кейса 2]
...

### [Название кейса 3]
...

## Инструменты и навыки

- AI: RAG, LLM, промпт-инжиниринг, агентные цепочки
- Данные: AOS-аналитика, метрики обучения
- Инструменты: Python (чтение), Git, API, GitHub Pages
- Методология: AI Readiness, ROI-расчёты, педагогический дизайн

## Контакты

- LinkedIn: [ссылка]
- Email: [адрес]
- GitHub: [ссылка на репозиторий]
```

**Шаг 2. Включите GitHub Pages в настройках репозитория.**

1. Зайдите в репозиторий на GitHub
2. Settings → Pages (в левом меню)
3. Source: «Deploy from a branch»
4. Branch: `main`, папка `/ (root)`
5. Нажмите Save
6. Через 1–2 минуты сайт будет доступен по адресу `https://[ваш-username].github.io/[repo-name]/`

**Шаг 3. Проверьте и дополните.**

- Откройте ссылку на телефоне — как выглядит?
- Дайте ссылку одному человеку и спросите: «Что я делаю?» Если ответ совпадает с вашим позиционированием — ок. Если нет — правьте `index.md`.
- Добавьте раздел «Методология» (AI Readiness, ROI-подход) — это отличает вас от тех, кто «просто использует ChatGPT».

**Что можно добавить позже (не на этой неделе):**
- Отдельные страницы для каждого кейса (файлы `case-1.md` и т.д.)
- Раздел «Статьи и посты» со ссылками на LinkedIn
- Файл `portfolio.pdf` — PDF-версия для скачивания
- Навигацию между страницами
- Кастомную тему Jekyll для красивого оформления

### 2.4. LinkedIn: секция «О себе» с AI-нарративом + Featured

LinkedIn — не цифровая копия резюме. Это место, где вас находят. Рекрутер видит: фото, заголовок, «О себе» — и за 5 секунд принимает решение: читать дальше или пролистнуть.

**Три элемента, которые работают на вас:**

**1. Заголовок (Headline) — 120 символов.**

Не должность. Результат + специализация + AI.

| Слабо | Сильно |
|---|---|
| «Руководитель отдела обучения» | «L&D × AI: сокращаю время на онбординг и разработку курсов вдвое» |
| «Методист, 15 лет опыта» | «Методист → EdTech-продюсер: строю AI-решения для корпоративного обучения» |
| «Learning & Development Manager» | «Head of L&D: AI-стратегия, data-driven-обучение, performance consulting» |

**Формула заголовка:** [Роль / специализация]: [что делаете] + [чем отличаетесь].

**2. Секция «О себе» (About) — до 2600 символов.**

Структура (используйте elevator pitch на 2 минуты из Урока 1):

```
[Кто вы — 1 предложение]

[Что делаете с помощью AI — 2–3 предложения]

[Ключевой результат — 1 предложение + цифра]

[Кого ищете / какую задачу хотите решать]

[Контакт или ссылка на портфолио]
```

**Пример:**

```
17 лет в корпоративном обучении, последние 2 года — интеграция AI в L&D-процессы. Перевожу отделы обучения с «курсовой фабрики» на data-driven-подход: от AI-аудита до дорожной карты внедрения.

Что делаю:
— Сокращаю time-to-competence новых сотрудников с помощью AI-агентов для онбординга
— Автоматизирую анализ обратной связи (то, на что методист тратил неделю, теперь 20 минут)
— Считаю ROI AI-внедрения до запуска, а не после

Последний проект: AI-агент для онбординга сократил отток новичков с 22 % до 10 % за 6 месяцев.

Открыта к ролям Head of L&D / Senior L&D Manager / EdTech-продюсер. Рассматриваю офис, гибрид и удалёнку.

Портфолио: [ссылка на GitHub Pages]
```

**3. Featured (Избранное) — витрина портфолио.**

Это секция, которая видна сразу под «О себе». Сюда добавьте:
- Ссылку на ваш GitHub Pages (сайт-визитку)
- Пост с одним из ваших кейсов (опубликуйте его на LinkedIn)
- Презентацию или документ с описанием AI-проекта

**Как добавить:** Profile → Add profile section → Featured → Add a link / Add a post.

**Адаптация под рынок (если вы ищете работу):**
- Уберите внутренние названия должностей и компаний, которые ничего не говорят внешнему рынку (аббревиатуры, отраслевой жаргон). Замените на общепринятые: не «ПЧ», а «руководитель производственного подразделения».
- Ключевые слова из вакансий, на которые вы откликаетесь, должны быть в заголовке и «О себе» — LinkedIn ищет по ним.
- Если вы меняете географию — укажите город. Если только планируете переезд — напишите «открыта к переезду в [город]».

## 3. Шпаргалка (сохраните себе)

### Термины

| Термин | Определение одним предложением |
|---|---|
| GitHub Pages | Бесплатный хостинг от GitHub: Markdown-файлы из репозитория автоматически становятся сайтом |
| Featured (LinkedIn) | Секция профиля под «О себе», куда можно добавить ссылки и посты — ваша витрина |
| Headline | Заголовок профиля LinkedIn (120 символов) — первое, что видит рекрутер после фото |
| Портфолио (L&D × AI) | 3 кейса с результатом, а не список курсов и программ |
| Index.md | Главная страница сайта на GitHub Pages — ваш `README`, который стал лендингом |

### Структура сильного портфолио

```
1. Заголовок (ваше имя + позиционирование)
2. О себе (elevator pitch 2 минуты)
3. Кейс 1 (задача → решение → результат → ваша роль)
4. Кейс 2
5. Кейс 3
6. Инструменты и навыки
7. Контакты (LinkedIn, email, GitHub)
```

### LinkedIn: checklist

```
[ ] Headline содержит результат + AI (не должность)
[ ] About структурирован: кто → что делаю → результат → кого ищу
[ ] Featured: ссылка на GitHub Pages + 1 пост-кейс
[ ] Город указан (особенно при переезде)
[ ] Ключевые слова из целевых вакансий есть в тексте
```

### GitHub Pages: checklist

```
[ ] Создан файл index.md с именем, позиционированием и 3 кейсами
[ ] В настройках репозитория включён GitHub Pages (branch: main)
[ ] Ссылка открывается и читается за 30 секунд
[ ] В index.md есть контакты (LinkedIn, email)
```

### Упражнение 2. Структура портфолио: отберите 3 кейса (20 мин)

Из всех артефактов выберите 3, которые станут вашим портфолио. Критерии отбора:

- В каждом кейсе понятна задача и измеримый результат (или оценка)
- Кейсы показывают разные компетенции (например: агент + аналитика + стратегия, а не три агента)
- Хотя бы в одном кейсе есть AI
- Вы можете уверенно рассказать о своей роли в каждом

**Заполните на каждый кейс:**

```
### Кейс [номер]: [заголовок — глагол + объект + результат]

**Контекст:** [1 предложение — где, для кого, масштаб]
**Задача:** [1 предложение — боль бизнеса]
**Решение:** [2–3 предложения — что сделали, инструменты]
**Результат:** [1 предложение + цифра]
**Моя роль:** [1 предложение — ваш вклад]
```

**Проверка:** если у вас 3 кейса, но все про «собрала AI-агента» — замените два на что-то другое (аналитика, стратегия, контент, методология). Портфолио должно показывать широту, а не глубину в одной точке.

### Упражнение 3. GitHub Pages: создайте сайт-визитку (40 мин)

**Шаг 3. Включите GitHub Pages:**
1. Откройте репозиторий на GitHub в браузере

**Шаг 4. Проверьте:**

- Проверьте, что файл называется `index.md` (не `INDEX.md`, не `index.txt`)

## 8. Что дальше

Вы прошли все 4 модуля программы «L&D × AI: учебный стек». У вас есть:

- Технический минимум: терминал, Git, API (Модуль 1)
- AI от промпта до продукта: RAG, агенты, fine-tuning (Модуль 2)

**Что делать дальше:**

1. **Поддерживайте портфолио в актуальном состоянии.** Появился новый проект — добавьте кейс. Устарел старый — замените. GitHub Pages — живой документ, не музей.

2. **Публикуйте кейсы как LinkedIn-посты.** Один кейс = один пост в месяц. Формат: «Задача → что сделала → результат → урок». Это поддерживает видимость и тренирует подачу.

3. **Следите за метриками.** Через месяц после обновления LinkedIn проверьте: сколько просмотров профиля, сколько входящих сообщений. Если ноль — экспериментируйте с заголовком.

4. **Используйте narrative на собеседованиях.** Перед каждым интервью открывайте `career/narrative.md`, проговаривайте 30-секундную и 2-минутную версии вслух.

5. **Работайте над скоростью.** 80 % вашей ценности должно быть понятно за 5 секунд (headline + первая строка About). Остальные 20 % — для тех, кто заинтересовался.

### Дополнительно (необязательно, но полезно)

- **GitHub Pages — кастомная тема.** Если хотите красивее, чем стандартный Markdown: добавьте файл `_config.yml` с темой Jekyll (например, `theme: jekyll-theme-minimal`). Инструкция: https://docs.github.com/en/pages/setting-up-a-github-pages-site-with-jekyll
- **PDF-версия портфолио.** Сделайте скриншот вашего GitHub Pages или конвертируйте `index.md` в PDF. Прикрепляйте к откликам на вакансии. 
- **Видео-визитка.** Запишите 30-секундный elevator pitch на камеру телефона. Прикрепите к LinkedIn Featured. Живое видео работает сильнее текста.
- **Полезная привычка.** Раз в месяц открывайте свой GitHub Pages и LinkedIn. Если вы сами за 5 секунд не понимаете свою ценность — правьте. Ваше портфолио устаревает быстрее, чем вы думаете.
