## 2. Теория

### Что такое API

API (Application Programming Interface) — это способ, которым одна программа просит что-то у другой программы. Проще всего представить официанта в ресторане:

- Вы (клиент) говорите официанту: «Принесите кофе» (запрос).
- Официант идёт на кухню, находит кофе и приносит вам (ответ).
- Вы не идёте на кухню сами, не знаете, как устроена кофемашина. Вам нужно только знать меню (документацию API).

API работает так же. Вы отправляете запрос по адресу (URL), сервер отвечает. Вы не знаете, что внутри сервера. Вы знаете только то, что описано в документации.

**Пример из жизни AI:** когда вы пишете вопрос в ChatGPT, браузер отправляет API-запрос к серверу OpenAI. Текст вопроса улетает туда, модель обрабатывает его и возвращает ответ. Всё, что вы видите в интерфейсе — это красивая обёртка над API-запросами.

### HTTP-методы: GET и POST

API-запросы бывают разных типов. Два основных:

| Метод | Что делает | Бытовая аналогия |
|---|---|---|
| **GET** | Запросить данные. «Дай мне вот это» | Посмотреть меню на сайте ресторана |
| **POST** | Отправить данные. «Вот тебе информация, обработай» | Оформить заказ с доставкой — вы отправляете адрес и состав |

GET-запрос просто читает. Вы открываете страницу в браузере — это GET. POST-запрос отправляет данные на сервер: форма на сайте, запрос к AI-модели, загрузка файла.

Есть и другие методы (PUT, DELETE, PATCH), но в 80 % случаев вы встретите GET и POST.

### JSON: язык, на котором говорят API

API отвечают в формате JSON (JavaScript Object Notation). Это способ записать данные так, чтобы их легко читал и человек, и машина.

Вот как выглядит JSON:

```json
{
  "имя": "Анна",
  "возраст": 34,
  "должность": "методист",
  "навыки": ["L&D", "AI", "презентации"],
  "проект": {
    "название": "Бустер методиста",
    "статус": "активен"
  }
}
```

Правила простые:
- `{ }` — объект (как анкета)
- `[ ]` — список (массив)
- `"ключ": значение` — пара (ключ всегда в кавычках, значение может быть строкой, числом, true/false, объектом или списком)

Почти каждый API-ответ выглядит как JSON. Научиться его читать — как научиться читать квитанцию: сначала кажется китайской грамотой, через неделю — привычно.

### Статус-коды: что ответил сервер

Сервер на каждый запрос возвращает не только данные, но и код — три цифры, которые говорят, всё ли в порядке:

| Код | Значение | Когда видите |
|---|---|---|
| **200** | OK. Всё хорошо, данные пришли | Успешный запрос |
| **201** | Created. Что-то создано (после POST) | Успешно отправили данные |
| **400** | Bad Request. Вы отправили что-то не то | Ошибка в запросе |
| **401** | Unauthorized. Нужен ключ доступа | Забыли API-ключ |
| **404** | Not Found. Такого адреса нет | Ошиблись в URL |
| **429** | Too Many Requests. Слишком частые запросы | Превысили лимит |
| **500** | Internal Server Error. Сервер сломался | Проблема не у вас |

Мнемоника: 2xx = успех, 4xx = ваша ошибка, 5xx = ошибка сервера.

### API-ключ: ваш пропуск

Большинство AI-API требуют ключ (API key) — длинную строку, которую вы передаёте вместе с запросом. Это как билет на концерт: без него вас не пустят, и он именной. Ключ нельзя публиковать в открытом доступе (попадёт в Git — считайте, что его украли).

### Как читать чужой код

Вы не будете писать код с нуля. Но вы будете его **читать**: скрипт коллеги, пример из документации, AI-сгенерированный файл. Чтение кода — это навык отличать лес от деревьев.

При встрече с незнакомым файлом задайте себе три вопроса:
1. **Что на входе?** — какие данные получает программа (файл, API-ответ, ввод пользователя)?
2. **Что внутри?** — какие шаги выполняются (прочитать → обработать → отправить)?
3. **Что на выходе?** — что программа отдаёт (файл, ответ в терминал, запрос к API)?

Для чтения кода не нужно знать язык досконально. Нужно видеть структуру: импорты (что подключаем), функции (блоки действий), вызовы (где что запускается). Остальное — детали.

**Метафора:** чтение кода — как чтение рецепта на незнакомом языке. Вы не знаете всех слов, но понимаете: «взять X, смешать с Y, поставить в духовку на Z минут». Импорты — список ингредиентов, функции — шаги рецепта, вызов — «духовку включить».

## 3. Шпаргалка (сохраните себе)

### API-запросы в PowerShell

PowerShell умеет отправлять API-запросы через встроенную команду `Invoke-RestMethod`. Она автоматически превращает JSON-ответ в читаемые объекты.

| Действие | Команда |
|---|---|
| GET-запрос (получить данные) | `Invoke-RestMethod -Uri "https://адрес"` |
| GET с параметрами | `Invoke-RestMethod -Uri "https://адрес?параметр=значение"` |
| POST-запрос (отправить JSON) | `Invoke-RestMethod -Uri "https://адрес" -Method Post -Body '{"ключ":"значение"}' -ContentType "application/json"` |
| POST с заголовками (API-ключ) | `Invoke-RestMethod -Uri "https://адрес" -Method Post -Headers @{"Authorization"="Bearer ключ"} -Body '...'` |
| Сохранить ответ в переменную | `$ответ = Invoke-RestMethod -Uri "..."` |
| Посмотреть поле ответа | `$ответ.поле` или `$ответ[0].поле` |

**Важно:** В PowerShell есть команда `curl`, но это не настоящий curl, а алиас для `Invoke-WebRequest`. Для API-запросов лучше использовать `Invoke-RestMethod` — он умнее обрабатывает JSON.

### JSON навигация

| Что видите | Как читать |
|---|---|
| `{"total": 42, "items": [...]}` | Объект с полями `total` (число) и `items` (список) |
| `$ответ.total` | 42 — доступ к полю через точку |
| `$ответ.items[0]` | Первый элемент списка |
| `$ответ.items[0].name` | Поле `name` первого элемента |

### Статус-коды — коротко

| Диапазон | Значение |
|---|---|
| 2xx | Успех |
| 3xx | Перенаправление |
| 4xx | Ошибка на вашей стороне |
| 5xx | Ошибка на стороне сервера |

### API-документация: где читать

Документация любого API обычно лежит по адресу вроде `https://платформа.com/docs` или `https://docs.платформа.com`. Что там искать в первую очередь:

- **Quickstart / Get Started** — как сделать первый запрос за 5 минут
- **Authentication** — как получить и передать API-ключ
- **Endpoints** — список всех доступных запросов (URL + метод)
- **Example request / response** — пример запроса и ответа (копируете и пробуете)

### Структура кода: что искать глазами

| Элемент | Как выглядит в Python | Как выглядит в JavaScript |
|---|---|---|
| Импорт (подключение библиотек) | `import json`, `from openai import OpenAI` | `const axios = require('axios')`, `import { OpenAI } from 'openai'` |
| Функция (блок действий) | `def имя():` с отступом | `function имя() { }` или `const имя = () => { }` |
| Вызов API | `requests.get(url, headers=...)` | `fetch(url, { method: 'POST', ... })` |
| Переменная | `x = 5`, `data = {...}` | `let x = 5`, `const data = {...}` |
| Условие | `if x > 0:` | `if (x > 0) { }` |
| Цикл | `for item in list:` | `for (let item of list) { }` |

### Упражнение 1. Первый GET-запрос (10 мин)

Самый простой API-запрос — получить данные по адресу. Используем бесплатный тестовый API, который не требует ключа.

Откройте PowerShell и выполните:

```powershell
Invoke-RestMethod -Uri "https://jsonplaceholder.typicode.com/todos/1"
```

Вы увидите что-то вроде:

```
userId  id  title                     completed
------  --  -----                     ---------
     1   1  delectus aut autem        False
```

PowerShell распознал JSON и показал его таблицей. Это объект с полями `userId`, `id`, `title`, `completed`.

Теперь запросите список задач:

```powershell
$todos = Invoke-RestMethod -Uri "https://jsonplaceholder.typicode.com/todos"
$todos.Count
```

Вы увидите общее количество — 200 задач. Теперь посмотрите первую и последнюю:

```powershell
$todos[0]
$todos[-1]
```

Поздравляю — вы только что сделали свой первый API-запрос и разобрали ответ.

### Упражнение 2. API с параметрами (10 мин)

Многие API позволяют фильтровать данные через параметры в URL. Параметры идут после знака `?`:

```powershell
Invoke-RestMethod -Uri "https://jsonplaceholder.typicode.com/todos?userId=1"
```

Вы получили задачи только пользователя с ID=1. Попробуйте `userId=2`, `userId=3`.

Теперь попробуйте другой публичный API — поиск книг:

```powershell

$books.docs.Count
$books.docs[0].title
```

Вы получили список книг по запросу "learning design" и посмотрели название первой.

### Упражнение 4. POST-запрос: отправляем данные (15 мин)

GET-запросы просто читают. POST — отправляют данные на сервер. Попробуем на тестовом API:

```powershell
$body = @{
    title  = "Моя тестовая задача"
    body   = "Учусь отправлять POST-запросы"
    userId = 1
} | ConvertTo-Json

$response = Invoke-RestMethod -Uri "https://jsonplaceholder.typicode.com/posts" -Method Post -Body $body -ContentType "application/json"
$response
```

Вы увидите созданный объект с полем `id: 101` — сервер подтвердил создание. Обратите внимание: `ConvertTo-Json` превращает объект PowerShell в JSON-строку.

Теперь разберите команду по частям:
- `@{}` — создали объект PowerShell (хэш-таблицу)
- `| ConvertTo-Json` — превратили в JSON
- `-Method Post` — указали метод
- `-Body $body` — передали данные
- `-ContentType "application/json"` — сказали серверу, что это JSON

### Упражнение 6. Чтение чужого кода (25 мин)

Ниже — скрипт на Python, который обращается к AI-модели через OpenRouter API. Ваша задача — не написать такой же, а **прочитать и объяснить**, что он делает.

```python
import os
import requests
import json

# --- 1. Настройки ---
API_KEY = os.environ.get("OPENROUTER_API_KEY")
MODEL = "google/gemini-2.0-flash-001"
API_URL = "https://openrouter.ai/api/v1/chat/completions"

# --- 2. Запрос ---
system_prompt = "Ты — L&D-методист. Отвечай коротко, по делу."
user_question = "Объясни разницу между RAG и fine-tuning одной фразой."

headers = {
    "Authorization": f"Bearer {API_KEY}",
    "Content-Type": "application/json"
}

payload = {
    "model": MODEL,
    "messages": [
        {"role": "system", "content": system_prompt},
        {"role": "user", "content": user_question}
    ],
    "temperature": 0.3,
    "max_tokens": 100
}

# --- 3. Отправка ---
response = requests.post(API_URL, headers=headers, json=payload)

# --- 4. Обработка ответа ---
if response.status_code == 200:
    answer = response.json()
    print(answer["choices"][0]["message"]["content"])
else:
    print(f"Ошибка {response.status_code}: {response.text}")
```

### Упражнение 8. Бонус: открытый API-ключ OpenRouter (15 мин, опционально)

Если у вас есть аккаунт на OpenRouter (openrouter.ai), вы можете сделать реальный запрос:

1. Зайдите на https://openrouter.ai/keys
2. Нажмите **Create Key**, скопируйте ключ.
3. НЕ вставляйте ключ в код. В PowerShell выполните:

```powershell
$env:OPENROUTER_API_KEY = "ваш-ключ-сюда"
```

4. Теперь отправьте запрос к бесплатной модели:

```powershell
$headers = @{
    "Authorization" = "Bearer $env:OPENROUTER_API_KEY"
    "Content-Type"  = "application/json"
}

$body = @{
    model    = "google/gemini-2.0-flash-001"
    messages = @(
        @{ role = "user"; content = "Привет! Кто ты и что умеешь?" }
    )
} | ConvertTo-Json -Depth 3

$response = Invoke-RestMethod -Uri "https://openrouter.ai/api/v1/chat/completions" -Method Post -Headers $headers -Body $body
$response.choices[0].message.content
```

Вы получили ответ от AI-модели через API. Поздравляю — вы на шаг ближе к тому, чтобы собрать своего AI-агента.

**Важно:** после эксперимента удалите ключ из переменной окружения (закройте PowerShell) и никогда не публикуйте ключ в Git.
